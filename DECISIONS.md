## Repository and tooling

- Repository root is `~/Source/Thorp` (the brief's `thorp/`); the package is `thorp/` inside it, built with hatchling so `uv run thorp` works.
- Python pinned to 3.12 with `.python-version`; `pytest` and `ruff` are in a `dev` dependency group, not runtime dependencies.
- Ruff selects E, F, I, B, UP and ignores E501, since `ruff format` owns line length (100) and a few docstring lines run over.
- `thorp/paths.py` (not in the layout) is the one place paths are decided; `THORP_DATA` and `THORP_LEDGER` override them so tests run in a temporary directory.
- `thorp/chinchilla.py` (not in the layout) holds the section 11 formula so the dashboard and README share it.
- `thorp id SPEC` was added to print a spec's run id without running it.
- `thorp ledger SQL [PARAMS...]` binds every `?` to the most recent finished run when no parameters are given (or to `--run ID`), so the section 10 query runs as written.

## Acquisition

- The User-Agent names the project and reads its contact from `THORP_CONTACT`; no personal email is hard-coded into the repository.
- Resolver language match is "the row's language is one of the catalogue row's `;`-separated languages", since a few catalogue rows list two.
- Title normalisation is NFKD, drop combining marks, lowercase, punctuation to spaces, collapse whitespace; CJK passes through unchanged.
- The author "surname" is the last word of the normalised author field; a row with no author is matched on title alone.
- Book ids are `pg<gutenberg id>` (for example `pg1342`), so the source is visible in every shard name and ledger row.
- Raw downloads are cached as `data/texts/gutenberg/{id}.txt`; stripping happens on read, so a better stripper never needs a re-fetch.
- The manifest `set` column is inferred from the list's filename (`hole` in the name means `hole-card`).
- Licence removal when there is no END marker cuts at the first line beginning "End of (the) Project Gutenberg" or "*** END OF" or "START: FULL LICENSE".
- `data/resolution.csv` holds every list fetched so far; refetching a list replaces only that list's rows.
- Overrides (`lists/overrides.csv`) pick the right volume or translation where the resolver chose wrongly: Thousand Nights vol. 1 (3435, not vol. 10), Herodotus vol. 1 (2707, not vol. 2), Divine Comedy Longfellow complete (1004, not Norton), Dhammapada Max Müller (2017), Nibelungenlied Needler (7321), Kalevala Kirby vol. 1 (25953), Consolation of Philosophy H. ## Tokeniser, shards and data

- Tokeniser id is SHA-1 of the sorted book ids; settings that differ from the defaults (vocab 16384, byte fallback, coverage 0.9995) are appended to the key, so another vocabulary on the same books is a different directory.
- SentencePiece is trained lossless: identity normalisation, no dummy prefix, extra whitespace kept, newline as a user-defined piece, digits split. `decode(encode(text)) == text`, so bits per byte charges for every byte, whitespace and line breaks included.
- SentencePiece samples at most 4 million lines (`input_sentence_size`) with `max_sentence_length=16384`; ids are unk 0, bos 1, eos 2, no pad.
- Byte-fallback rate per book (fraction of tokens that are byte pieces) is in `stats.json` beside bytes per token.
- Shards are written to a temporary name and renamed, so an interrupted write never leaves a half shard that would be "written once".
- Hole-card books are also sharded (under the run's tokeniser) so evaluation tokenises once; they are never in a recipe or in tokeniser training.
- `order: shuffled` means: books concatenated in a seeded shuffle per pass, cut into non-overlapping `context + 1` windows, and the windows themselves dealt in a seeded shuffle into batches. Without the window shuffle every batch would be 32 consecutive windows of one book.
- A window's family (for the per-batch family mix) is the family of the book its first token comes from; the mix is logged as `data/family/<family>` every 50 steps.
- The remainder of a pass that does not fill a batch is dropped.

## Model and training

- The "9m" preset as specified (6 layers, width 192) has 2.66M non-embedding and 3.34M embedding parameters (6.0M total, 16,384 × 192 token plus 1,024 × 192 position embeddings), not the brief's "about 6M non-embedding + 3M embedding". The layer and width table wins; N in the Chinchilla formula is the measured non-embedding count.
- A `tiny` preset (2 layers, width 64) exists for tests only.
- LayerNorm without bias, GELU (tanh approximation), initialisation N(0, 0.02) with output projections scaled by 1/√(2·layers).
- Attention uses `mx.fast.scaled_dot_product_attention` with a causal mask.
- "bf16 parameters with fp32 optimiser state": the model computes in bf16; the optimiser keeps an fp32 master copy of the weights plus fp32 Adam moments, and the bf16 weights are refreshed from the master after every step. Checkpoint `model.safetensors` holds the fp32 master.
- Weight decay (0.1) applies to every parameter, norms and embeddings included (MLX AdamW's default); no bias correction (MLX's default).
- Learning rate: linear warmup over 200 steps to 1e-3, then cosine to 1e-4 at the last step.
- The loss and its gradient are compiled with `mx.compile` (model state as inputs and outputs); clipping and the optimiser step run eagerly in fp32.
- Steps are numbered from 1 (step N is after N updates); evaluation runs at every multiple of `eval.every_steps` and at the final step; checkpoints at every multiple of `checkpoint.every_steps` and at the final step.
- `param_norm` is the L2 norm of the fp32 master weights; `grad_norm` is the pre-clip global norm.
- On resume, ledger rows recorded after the checkpoint step are deleted, so the metric series has no duplicates; wall time accumulates across resumes via `state.json`.
- A run that raises is marked `failed: <ExceptionType>` in `runs.status`.
- The git commit recorded is `HEAD`, with `-dirty` when tracked files have uncommitted changes.

## Evaluation

- Each held-out book is scored as `[EOS] + tokens + [EOS]`, so every token is predicted once with no free first token; `tokens` in the evals row is the number of predictions (book tokens + 1).
- Windows do not overlap; each starts with an empty context, which slightly overstates loss relative to a sliding window.
- Set means are unweighted means over books; `eval/<set>/ce_mean_en` and `bpb_mean_en` are the same over English books only, and the Chinchilla gap uses `ce_mean_en`.
- Missing hole cards are listed in the run's `eval_sets` artifact (`missing`) and in the run log, since the `runs` table has no column for them.
- Samples are stored as one `samples` artifact (JSON list of prompt, temperature, text) and one `top10` artifact per eval step; temperature sampling is seeded by the step.
- Determinism: on the GPU, MLX's embedding-gradient scatter-adds are not bitwise reproducible (about 1e-9 in fp32, 6e-5 in bf16), and Adam amplifies this, so two identical GPU runs drift apart. The resume test therefore runs on the CPU, where MLX is bitwise reproducible; the seed-2 run measures the run-to-run spread that matters.

## The observation layer and the next runs (6 November, evening)

- The loss function returns the per-window losses beside the batch mean (MLX passes auxiliary outputs through `value_and_grad` and `compile`); the mean of the window means is the batch mean, so the `loss` row is unchanged. Window losses are summed per recipe book and written every 50 steps as `loss/book/<id>` (the mean over that window), never per step: a hundred books at every step would be most of the ledger.
- The sieves are per parameter group from `model.param_groups()`: `tok`, `pos`, `layer_i`, `layer_i/attn`, `layer_i/mlp`. Every 50 steps: `grad_norm/<g>` (pre-clip push), `param_norm/<g>` (size of the fp32 master), and once a full 50-step window has passed since the last record, `update_norm/<g>` (the move since then) and `update_ratio/<g>` (move over size). The step-1 record carries no move. `grad_norm/layer_i` keeps its old name and value.
- The kink (where a layer's push changes regime) is computed on the page from the rows, as the least-squares break of a two-line fit to log10 of the norm, and is never stored: it is derived, like everything else the page shows.
- Trait probes (`evaluators/probes.py`): difference-of-means directions fitted on eight evenly spaced windows per recipe book, scored on sixteen per hole card, per layer, as an AUC. Found means held-out AUC ≥ 0.8 at some layer with at least two hole cards on each side; thinner than that is `untestable`, so a direction can never be a book-identity direction in disguise. Labels come from `lists/traits.csv` by list title (fiction, verse, first_person; blank skips the book for that trait) and the family one-vs-rest from the manifest. The `probes` artifact carries every trait's status and reason; `probe/<trait>/layer_i` and `/best` are the metric rows.
- The first sample prompt is a law of physics ("For every action there is an equal and opposite"), not the capital of France: a law does not move with the date, and no book on the shelf states it, so the bar for "reaction" is a tracer for a textbook shelf. The other three are first lines of books on the shelf and are a memory check, labelled as one on the page. The top-10 artifact carries its prompt.
- The page is read in sections (Betting, Books, Languages, Sieves, Attention, Traits, Runs) with a nav bar; the claim panel at the top states the hypothesis, the measure, the prediction and the falsifier, and computes the ledger's reading (best shelf, shelf-to-shelf difference, seed spread, which side of twice the spread). `/api/compare` serves every run's hole-card bpb against tokens seen for it; `/api/run` joins the traits and the latest `probes` artifact.
- `specs/smoke-10-v2.yaml` is smoke-10 with the probes evaluator; `hundred-by-reach-v1-seed2.yaml` keeps its original spec because the run had already started on it (the error bar must not change under the run).
- The pool (`scripts/make_pool.py`): the earliest Gutenberg transcriptions, by id, that pass both legal checks on the catalogue's own author dates (a person without dates is refused), no periodicals or index entries, no edition of a hole card by title, nothing already in the manifest. Family from the subject tags for translations, Germanic for an English original. Fiction and verse labels come from the subject tags; first_person is left blank. 560 drawn (ids 1..816); `scripts/cut_pool.py` keeps the hundred plus the first 300 of at least 100 KB as `lists/pool-400.csv`, and cuts the fiction and non-fiction halves to the same bytes within 2%.
- The next shelf is sized to the model, not the hand: about 400 books read twice, roughly 65M unique and 130M seen tokens, against Chinchilla's twenty tokens per parameter (53M to 120M for this preset). Six specs: the pool, its fiction half, its non-fiction half, each with two seeds, in that order, queued by `scripts/queue_next.sh` after seed-2 and the fetch.
- `scripts/` holds one-off builders and the queue; they are not part of the package and read the repository paths directly.
- Every spec carries a `ship`: a short name for the run (Dinghy, Argo, Endeavour, Hispaniola, Mayflower; II for seed 2). `name` and `ship` are the two keys left out of the run id, so naming a run never changes it; the ledger's `runs` table gained a `ship` column (added in place on an older ledger) and the page shows the ship wherever a run is named. The three runs already on the ledger were named by hand.
- The page's sections are tabs (one shown at a time, chosen by the URL hash, charts resized on show), so a person navigates the deck rather than scrolling it.
- The overview strip carries four things only: the ship (with run name, id and status), the kink findings in one line (firm kinks by layer with which way they went, the tentative count, the earliest), tokens a second, and the ETA (wall time once finished). Preset, tokens seen, the hole-card mean and the Chinchilla yardstick moved to a strip at the top of the Betting tab. The kink fit starts where warmup ends (the learning-rate peak); a kink is firm after ten records when the two-line fit removes a quarter of the one-line residual, and is labelled turned up, turned down, flattened, steepened, eased or bent by the signs of the two slopes.

Before this, a re-score cleared every evals row at the step.

- The Betting tab's matched-tokens table interpolates each run's own first eval set linearly at 16M, 32M and 64M tokens and leaves a dash outside the curve (no extrapolation); `/api/compare` now carries every set a run was scored on (`by_set`) and the per-layer push and learning rate, so the page computes each run's earliest firm kink with the same fit as the Sieves tab. The truth gap is `truths` minus `hole-cards-v2` (or `hole-cards` if the run has no v2 rows) at the same step; with only a final-step re-score it is one point per run, and the "change since first scored" column fills only for runs that train with the truths deck in `eval.sets`.
- Endeavour started at 20:09, while these edits were being made; the training loop is unchanged by them (the scoped `clear_step` deletes the same rows when the sets are the run's own), and its commit reads `-dirty`.
- Trait floors (`probes`): each tested trait also gets `floor_bow` (the same difference-of-means probe on each window's token histogram, projected as the mean of the direction over the window's tokens, so no window-by-vocabulary matrix is built) and `floor_init` (the probe on the run's model at initialisation, `train.init_model`, built from its own seed and cached once per run). `emergent` is found and best AUC at least 0.05 above both floors. The page splits YES into "emergent" and "in the tokens". A floor that raises is recorded on the trait as `floor_error` and never fails the run: the queued training runs after Endeavour load this code. `build_model` reseeds MLX's global generator, which is safe mid-run only because training draws nothing from it after the model is built (the data order is numpy with explicit seeds; samples use explicit keys).
- The curiosity ladder (`evaluators/curiosity.py`): six rungs on the held-out books, each against the untrained model and, for the two probe rungs, a bag of tokens. Thresholds are constants at the top of the module and in each `curiosity` artifact: calibration r ≥ 0.3; novelty and question AUC ≥ 0.8 and 0.05 above the floors; late-minus-early loss ≤ −0.1 nats and copy gain ≥ 0.5 nats; expectancy and asking ≥ 0.1; rungs 1, 3, 5, 6 must also beat the untrained value by 0.1. Rung 2's familiar side and rung 4's fitting sentences are 64 evenly spaced recipe books. Rung 4 strips the end punctuation from questions and statements alike but keeps interrogative words, which the token floor accounts for. Rung 6 subtracts the text's own high/low ratio of question marks, so a model that only copies the text's habit scores zero. The ladder is in order when no present rung sits above an absent one, untestable rungs skipped. It runs in the re-score chain and in the phase 3 specs, not in the night's queue.
- The Traits tab reads every step's `probes` artifact (`/api/run` → `probes_all`, later rowid wins at a step), with a step selector and a sort: sieve layer (the layer where the held-out AUC peaks, with that layer's kink from the push), first step found (over every step on the ledger), best AUC, or name; the sort is remembered per viewer in localStorage. The half-life chart's labels are made unique with the book id: two volumes cut to 40 characters had shared one bar slot.
- Phase 3 specs are written and not started (`hundred-traits-v1`, `pool-400-traits-v1`, each with a seed-2 twin; ships Beagle and Resolution): eval every 100 steps on `hole-cards-v2` and `truths`, refusing all three held-out lists, with `ce_bpb`, `samples`, `probes` and `curiosity`. The held-out decks are about 27 MB, so an eval every 100 steps adds materially to each run's wall time; the brief's 2.5 hours for four runs is an underestimate.

## The content experiment, pre-registered before any shelf is cut (6 November, 20:50)

- **Question.** Holding the model, the tokens and the test fixed, does the shelf a model is trained on change how well it guesses books it has never seen, by more than chance alone does?
- **Ships.** Five shelves, three ships each, all at the 9m preset, English only, the same bytes and the same passes: Flotsam (three different random draws of legal English catalogue books, seeds 1 to 3: the null), Paralus (the Greek polis, primary texts), Dhow (the Islamic golden age, primary), Santa Maria (the continental Renaissance in English translation, primary), Cutty Sark (books written about those three ages by later authors). Primary texts arrive in translations printed 1800 to 1929; every person in a book's catalogue Authors field died by 1955.
- **Size rule.** Every shelf is cut to the same bytes B, the largest B at which every shelf can be filled with no single work above a third of it (a work counts once across its translations and volumes: all the Nights are one work, both Korans one, Jowett's Plato one, Vasari's Lives one, Grote's History one). B is set from the fetched sizes and recorded below this entry; the rule is not changed after the sizes are seen.
- **Primary measure.** English bits per byte on the `neutral` deck (held-out 19th and 20th century prose with no Greek, Islamic or Renaissance book in it), read at the same tokens for every ship: the smallest final tokens-seen of the fifteen, by linear interpolation.
- **The verdict rule.** Let F be the three Flotsam scores, its centre their mean and S their range. Content has a detectable bearing if some curated shelf's three-ship mean lies more than 2S from F's centre; otherwise it has none at this size and this shelf size, and that is the finding. Quality: a primary shelf differs from Cutty Sark if their means differ by more than twice the larger of the two shelves' ranges. Type: two ages differ by the same rule. The page computes all three from the ledger.
- **Secondary readings, not part of the verdict:** each age's own held-out deck (the transfer matrix), each ship's best point over training, the truths deck, the trait probes and the curiosity ladder.
- **Known limits, stated now:** translation is confounded with canonical (the primary shelves are translations, Cutty Sark and Flotsam mostly written in English); about 3M unique tokens a shelf is far below the 9m model's appetite, so a null says "not at 9m on shelves this size".
- **Addendum, 20:55, before any shelf is cut: content against traits, kinks and sieves.** The same rule (a curated shelf's three-ship mean more than 2S from the Flotsam centre, S the Flotsam range) is applied to four more outcomes, each a secondary verdict on the page: (1) traits: each testable trait's best held-out AUC at the final step, its emergent status against the floors, and its first step found; (2) kinks: the earliest firm kink step and each layer's firm kink step (push, two-line fit from the learning-rate peak); (3) sieves: each layer's mean log10 push and mean update ratio over the last quarter of training; (4) the curiosity ladder: the highest rung present. The probes test on every held-out book the ships are scored on (the neutral deck and the three age decks), so fiction, verse and first person all have books on both sides.
- **The content ships' optimiser differs from the earlier runs, the same for all fifteen:** `batch_tokens` 8192 (not 32768) and `warmup_steps` 100 (not 200), so a shelf of about 10 MB read four times is about 1,300 steps with about 24 sieve records after the learning-rate peak, enough to fit a kink. Evaluation every 200 steps. These runs are compared with each other, never with Argo or Endeavour.
- **Translations and legal checks for the shelves:** every person in the catalogue Authors field died by 1955 and has a death year (a person with no dates is refused); every translator, editor or adapter was born in 1760 or later, which keeps the translations to those printed in the 19th and early 20th centuries and excludes Early Modern English renderings (Urquhart's Rabelais, Robinson's Utopia, Fairfax, Sale, Scott); children's retellings (of the Nights above all) are excluded. The held-out books for each age (Greek, Islamic, Renaissance) are removed from that age's shelf.
- **Amendment, 21:00, after counting titles and before measuring any bytes: the one-third cap is dropped.** Under the legal rules the Islamic shelf outside the Nights is the Koran (Rodwell), Rumi (Redhouse's Mesnevi, Davis), Jami (Davis) and the Rubaiyat, about 3 MB, so the cap would have set every shelf near 3 MB, under a million tokens, and starved all fifteen ships. Instead B is the smallest shelf's whole size, every shelf is cut to B, and each shelf's largest-work share is recorded and shown beside its result. The Islamic shelf is therefore mostly the Nights (Burton, Payne, Lane, Forster), which is what the Islamic golden age is in English on Gutenberg; its result is read as that. Cherágh Ali's 1885 tract is off the Islamic shelf (a 19th-century argument, not a golden-age text). Burckhardt's Civilisation of the Renaissance is refused (its translator has no dates in the catalogue).
- **The cut (21:05).** B = 12.45 MB, set by the third random draw (38 books; the first two drew more than they needed). Every shelf is within 2% of B: Greek 52 books (Plato 55%), Islamic 14 (the Nights 91%), Renaissance 19 (Erasmus 33%), about the ages 15 (Symonds 40%), random 36, 27 and 38. About 3.4M tokens a shelf, four passes, about 1,640 steps at 8,192 tokens a batch. Books that did not fetch (no plain-text file, or unresolved) are simply not on their shelf. Evaluation every 400 steps (four times and the final step), so that the fifteen ships and the four kinks-against-traits ships fit before 07:00. The shelves' fiction and verse labels were read from the catalogue's subject and bookshelf tags (one step wider than the pool's subjects-only rule); first person is unlabelled on these shelves, so that trait reads untestable for them.
- **Ship names (21:05, Justin):** Banks-style names that say what each run is for, a label only (not hashed). Content: Whatever Washed Ashore (random; Something Else Washed Ashore and A Third Tide's Worth are the second and third draws), What Athens Wrote, Mostly The Thousand Nights, Florence, In Translation, Merely Describing Greatness; a second seed is "…, Rolled Again", a third "…, Third Roll". The night queue's unstarted ships were renamed in place (ids unchanged): Only Things That Happened (Mayflower), Four Hundred Books, Second Opinion (Endeavour II), Made-Up People, Rolled Again (Hispaniola II), Things That Happened, Rolled Again (Mayflower II). Hispaniola was already sailing and keeps its name.
- **Evaluator failures (21:13).** In `run_evaluators`, only `ce_bpb` (the score) may stop a run; any other evaluator that raises is logged, written as an `eval_error` artifact at that step, and skipped. The content ships are the first to run the curiosity ladder and the probe floors on real shelves during training, and all fifteen share that code, so an untested failure there must not cost the night. The page's run picker (header) sets the run every per-run panel shows; panels that compare every run are tagged ALL RUNS.

## The ladder: one job per size (6 November, late, Justin)

- **Five rungs, each with one job; these are the first class of ships.** Presets in `thorp/models/registry.py` (`67m` and `300m`, never run, became `50m` and `350m`; `100m` is new). Total parameters include the 16,384 × width token table and 1,024 × width positions.

  | --- | --- | ---: | ---: | --- | --- |
  | `9m` | 6 × 192 | 2.7M | 6.0M | this Mac mini | spelling, punctuation and the statistical laws of text |
  | `21m` | 8 × 320 | 9.8M | 15.4M | this Mac mini | grammar and style: agreement, sentences, register held through a passage |
  | `50m` | 12 × 512 | 37.7M | 46.7M | rented GPUs | paragraphs, and the third point for fitting this corpus's own size curve |
  | `100m` | 12 × 768 | 84.9M | 98.3M | this Mac mini (about 5 to 8 days) | the Origin test: the Mac's flagship |
  | `350m` | 24 × 1024 | 302.0M | 319.8M | rented GPUs | the top of the Origin curve |

- **The Origin test.** Trained only on English printed before *On the Origin of Species* (cutoff 1858, the Darwin–Wallace papers), does the model find natural selection less surprising than matched rival accounts (fixed species, Lamarckian inheritance, special creation), and does that preference grow with size and shrink when the precursor shelf (Malthus, Lyell, Paley, Chambers' *Vestiges*, the breeders, the *Beagle* voyage) is taken off at the same bytes? A base model does not derive; the claim is about betting, which is what this harness measures. The result is the curve over 9m, 21m, 50m, 100m and 350m, not any one model. Known hurdles: the catalogue carries no first-publication date (author death year is a strict stand-in that loses, for example, Dickens before 1859); revised editions leak (Lyell revised the *Principles* into the 1870s); translators' notes leak; and the pre-1858 English corpus is about 0.4B tokens when counted by the strict rule that every person in a book's Authors field died by 1858 (2,919 catalogue books at the mean fetched size; see `plans/leonardo-pilot.md`), so `350m` (about 6.4B tokens at twenty a parameter) will be short of data at that cutoff.
- **Rented GPUs need a second backend.** The harness is MLX-only (`registry.FAMILIES`), so `50m` and `350m` need a PyTorch model behind `thorp/models/backend.py`'s protocol before they can run off the Mac. Not built yet.
- **Each rung is tuned once, then frozen.** A rung's settings are swept against its own job first; its shelf experiments then run at the frozen settings, so the ledger's comparisons inside a rung stay like for like.

## The 9m rung's scoreboard and tuning sweep (6 November, late)

- **`bpb_split` evaluator** (`thorp/evaluators/bpb_split.py`): bits per byte on each held-out book split by the kind of byte predicted: `word_inside` (a letter after a letter: spelling), `word_start` (a letter after a non-letter: word choice), `punct` (Unicode P*), `space`, `newline`, `digit`, `other`. An apostrophe between letters counts as inside the word. A token's loss is shared evenly over its bytes, the convention under which the classes add back to the book's bits per byte weighted by byte share; the closing EOS has no bytes and is reported as `eos_bits`. Metrics `eval/<set>/split/<class>/bpb_mean[_en]` and `share_mean[_en]`; the per-book bits and bytes are the `bpb_split` artifact. Token bytes come from the pieces (`▁` is a space, `<0xNN>` a byte), checked to rebuild War and Peace byte for byte.
- `ce_bpb.book_ce` now sums per-token float64 losses from `book_losses` (which `bpb_split` shares) instead of float32 sums per batch; the score moves only at rounding, and the seed-2 pool runs that started after this edit run it.
- **`laws` evaluator** (`thorp/evaluators/laws.py`): the model writes 16 streams of 640 tokens from an empty context at temperature 1 (key seeded by the step); the reference is 16 excerpts of the English held-out books at fixed seeded character offsets; both are cut to 150 words a stream, so vocabularies that spend different tokens per word are measured on the same amount of text. Laws, each as `laws/model/<law>` and `laws/ref/<law>`: `nonword_rate` (words never seen in the recipe; the reference's rate is the floor), `zipf` (minus the log-log slope of frequency on rank over words seen twice or more), `heaps` (log-log slope of vocabulary on words read), `word_len`, `word_len_js` and `punct_js` (Jensen–Shannon divergence in bits from the reference's word-length and punctuation mix), `punct_per_100w`, `unbalanced_per_kw` (orphan or unclosed brackets and curly double quotes, plus odd straight double quotes, per thousand words) and `cap_after_stop` (share of sentence ends followed by a capital). Laws drift with sample size, so they compare across runs only at these constants. The written and reference texts are in the `laws` artifact. The recipe lexicon is built once per process.
- `run_evaluators` clears a step's evals rows only when `ce_bpb` is among the evaluators (the only one that writes them), so `thorp eval RUN --evaluators bpb_split laws` adds the split and the laws without touching the score.
- **The sweep** (`scripts/make_9m_specs.py`, order in `specs/9m-order.txt`): Endeavour's shelf, passes and optimiser with one setting changed, two seeds each, evaluators `ce_bpb bpb_split laws samples probes`: vocabulary 4,096 (*Smaller Pieces*) and 8,192 (*Half The Pieces*) against Endeavour's 16,384, and context 256 (*Short Memory*) against 1,024; seed 2 is "…, Rolled Again". The 16,384 / 1,024 cell is Endeavour and its seed 2, re-scored with the split and the laws. Same bytes, not same tokens: a smaller vocabulary spends more tokens and steps on the same shelf, and its embedding table is smaller (4,096 × 192 = 0.8M against 3.1M), which is the point. Bits per byte is fair across tokenisers.
- **The night's order changes (supersedes "content question first" in *Earn each size*):** `scripts/queue_9m.sh` replaces `scripts/queue_content.sh` (stopped while still waiting, before it ran anything). After `queue_next.sh` and `queue_rescore.sh` exit, it re-scores every finished 9m run with `bpb_split` and `laws`, runs the sweep, then the fifteen content ships and the four traits ships as before. The content and traits specs now also carry `bpb_split` and `laws` (none had started, so only their run ids move); their other settings are unchanged, so the content experiment's pre-registered rule stands. The content ships run at 16,384 whatever the sweep finds; if the sweep moves the 9m settings, later 9m shelf experiments use the new ones.

## Thorp against Qwen: the Forgotten Tomes (6 November, 23:40, Justin)

- **Goal.** Thorp's first version to compare with Qwen 3.8 27B is a 2.7B model: a tenth of the parameters. The comparison is Thorp's own measure, bits per byte on held-out books, which does not depend on the tokeniser, so both models are scored on exactly the same bytes.
- **The Forgotten Tomes** (`lists/hole-cards-unseen.csv`, drawn by `scripts/make_unseen_deck.py`; Justin's name): 16 English books, 7.7 MB, released on Gutenberg on or after 2026-08-05, the day Qwen/Qwen3.8-27B appeared on Hugging Face (its model card gives no data cutoff), so not in its training data by way of Gutenberg; every person in Authors born 1500 to 1880 and dead by 1955; 100 KB to 1 MB each. The metric is the **Forgotten Tomes score**: mean bits per byte on this deck, lower is better. Known limit: new to Gutenberg is not the same as never on the web (Goldsmith's essays and Wilson's History of the American People exist in other editions), so a book Qwen scores far better on than the rest is read as probably seen. No current recipe holds any of them (their Gutenberg ids are above 79,000, and every pool draw skips books already in the manifest); new specs should list it under `refuse`, and the re-score's refusal check would catch an overlap.

Qwen 3.8 27B is scored in the 4-bit MLX conversion (`mlx-community/Qwen3.8-27B-4bit`, 16 GB; the bf16 model needs 54 GB), which moves its score a little; Qwen 3.5 0.8B (bf16) is scored too as a small reference. ## The 1m proxy (6 November, 23:55, Justin: ahead of the 9m sweep)

- **Why.** A 9m speller run is about half an hour of training and an hour of evaluation; the outer loop (runs as steps, the Forgotten Tomes score as the error signal) needs far more, faster steps.
- **The preset** `1m`: 4 layers × 128, 4 heads, vocabulary 4,096 (at 16,384 a model this small would be mostly word table): 1.44M parameters (0.79M non-embedding). Peak learning rate 2e-3 (small models take a higher one), warmup 100. Lean evaluation: `ce_bpb` and `bpb_split` on the Forgotten Tomes only, once at the end. Measured 146k tokens a second (2.3 times 9m: overhead-bound at this size), so a Chinchilla-sized run (28M tokens) is about 3–4 minutes with its evaluation.

The proxy is trusted for a kind of question only if it ranks these as the 9m runs rank on the Forgotten Tomes (scored by `scripts/score_thorp_unseen.sh`). Deep traits are out of its reach by design.

## The order-of-magnitude gate, pre-registered (7 November, 00:05, Justin)

- **The test.** Thorp at about 60M parameters (the 50m rung or a little above: a tenth of the challenger) against Qwen3 0.6B (`mlx-community/Qwen3-0.6B-bf16`, released 2025-04, the smallest Qwen 3), both scored in bits per byte by the same window rule on two decks of unseen-since-Qwen period books: the Forgotten Tomes (redrawn balanced by kind, poetry included) and a sealed second deck drawn the same way and opened only for this verdict. Thorp's number is the mean of two seeds. If it passes, the same gate is run one rung up, until the 2.7B against Qwen 3.8 27B.
- **The binary verdict, PASS or FAIL.** PASS only if all of these hold, otherwise FAIL: (1) Thorp's mean bits per byte is at or below Qwen's on the Forgotten Tomes; (2) the same on the sealed deck; (3) the difference survives the noise: Thorp's two seeds both at or below Qwen.
- **Under a FAIL, one graded reading, with its caveats stated beside it:**
  - *Partial pass*: within 0.10 bits per byte of Qwen on both decks, or below Qwen on at least one kind of book (poetry, fiction, history, ...) on both decks.
  - *Partial loss*: behind by more than 0.10 on both decks, but below Qwen on at least one kind on one deck, or the gap to Qwen closing by more than a third from 9m to 50m (so the next rung could close it).
  - *Clear loss*: behind by more than 0.10 on both decks, no kind won on either, the gap not closing. The road is wrong as built; the recipe is rethought before any larger run.
- **Caveats always reported with the verdict:** Qwen's 1,024-token windows hold more bytes than Thorp's (an edge to Qwen); tomes on which Qwen beats its own deck mean by more than 0.5 bits per byte are flagged as probably seen elsewhere, and the verdict is also given without them; the training-data gap (Qwen 3 about 36T tokens, Thorp at most a few billion).

## The book-value loop (7 November, 00:40, Justin: "runs sequentially and you steer it")

- **Question.** What is each kind of book worth on the Forgotten Tomes, and how many readings does it repay? Answered by regression over many 1m runs on random shelves (the datamodels idea, Ilyas et al. 2022; the mixture-regression idea, RegMix 2024), so the 2.7B's few billion tokens can be chosen and repeated by value.
- **Pool** (`scripts/loop_pool.py`): the 1,108 fetched English books of the hundred and the two pool drafts, at least 20 KB, none a hole card, truth or Forgotten Tome; 457 MB. Features in `data/loop/features.csv`; six strata by kind (verse, fiction, non-fiction; verse first, and poetry is its own kind, Justin) and original or translated (the original's family is not Germanic, or the catalogue names a translator): fiction/original 620 books, fiction/translated 74, non-fiction/original 256, non-fiction/translated 40, verse/original 96, verse/translated 22.
- **Shared tokeniser** (`scripts/loop_prepare.py`): vocabulary 4,096 trained on the whole pool (`train_on: lists/loop-pool.csv`), every pool book and Forgotten Tome sharded once.

- **Steering** (the scheduled task `thorp-loop-steer`, every three hours, saved in Auto mode): keeps two loop lines pending in `specs/queue.txt` so the loop runs continuously, fixes clear failures, refits, and may change only the sampler's alpha (0.2 to 2.0), passes (from 1, 2, 4, 8) and stratum floor (0 to 0.1), at most once per 50 runs, never the bytes read; every action logged in `data/loop/steering.md`. Adding loop lines is the one change to the queue's order the overnight watches should expect.
- **Trust.** The loop's book values carry over only as far as the 1m proxy's calibration against 9m holds (that verdict lands first); the best and worst shelves it finds are confirmed at 9m and 21m before they shape the 2.7B.
- **Faster resolution:** `gutenberg.resolve` now normalises the catalogue once per process instead of once per list row (resolving the 1,108-book pool fell from 3 min 45 s to 8.5 s; results unchanged).
- **00:45, Justin: the loop is cut from 2,000 runs to 300, about 24 hours of the Mac** (2,000 would have taken about seven days). 300 runs is ample for the stratum-level fit (nine terms; RegMix fitted mixtures on 512 runs); per-book values were never within reach of 2,000 runs anyway, so the regression stays on book features. ## Nevermores (7 November, 01:00, Justin)

- **Name.** Thorp calls induction heads Nevermores, after Poe's "The Raven": once the reader has seen "Quoth the Raven" followed by "Nevermore", the next "Quoth the Raven" brings "Nevermore" before it is read. A Nevermore is an attention head that, at a word seen before, attends to the word that followed it last time (Olsson et al., 2022). They tend to form suddenly in training (a phase transition; Justin's metaphor for the moment is Helen Keller at the water pump).
- **Measure** (`thorp/evaluators/nevermore.py`, evaluator `nevermore`; `GPT.attention_patterns` computes every head's weights out in full, tested against the fused kernel): eight sequences of 200 random word pieces followed by the same 200 (seed 1845), and eight 200-piece passages of a Forgotten Tome (Goldsmith's essays) each followed by itself. Per layer and head, the mean attention from each piece in the second copy to the piece that followed it in the first. A head at 0.3 or more is a Nevermore; even attention would give about 0.003. Also the copy gain, the drop in loss from the first copy to the second. Metrics `nevermore/*` and `nevermore/natural_*`; the full layer x head matrices in the `nevermore` artifact.
- **Where.** Every unstarted spec in the queue now carries it (38 specs, every 250 steps where they evaluate that often, so formation can be timed); the loop runs carry it at their last step; `scripts/score_nevermore.sh` scores every finished 1m and 9m run once (queued).
- **First readings, at the last checkpoint:** no Nevermore anywhere yet. Endeavour's strongest head reaches 0.02 (random) and 0.019 (real prose); Argo's 0.006; Little Argo's 0.006. Smaller Pieces (9m, vocabulary 4,096) has a head forming in its top layer: 0.12 on real prose with a copy gain of 0.27 nats, but only 0.02 on random pieces. A smaller vocabulary means more, shorter pieces per passage, which may give copying more to gain; the seed-2 run and the 8,192 run will say.
- **Dashboard.** The dashboard was rebuilt as an Astro app (commit b5e31a2, `thorp/dash/UI.md`) while this was being written, and is being edited elsewhere, so the Nevermores panel is left to it: per run the latest `nevermore/max_score`, `count`, `natural_max_score`, `natural_count`, `natural_best_layer`/`natural_best_head` and `natural_copy_gain`, and `nevermore/natural_max_score` over steps with the 0.3 line.
- **01:10, Justin (through the dashboard session): Nevermores at every eval step, on every run.** All 37 queued specs already carry `nevermore` at each eval step (18 every 250 steps, the 15 content ships every 400, the 4 traits ships every 100), as does the running proxy. ## The copy-weighted tack, pre-registered (7 November, 07:45, Justin)

- **Idea.** Today every guess counts the same in the loss (w = 1). The only guesses that reward the stars are those the earlier text in the window could answer; the rest dilute their signal. The copy-weighted tack weights each guess w = 1 + alpha × [the target followed an earlier occurrence of the current token in the same window] ("induction", what a Nevermore can get right; a milder "duplicate" kind marks any target that appeared earlier in the window), normalised by the sum of the weights so the tack's size stays comparable. `optim.copy_weight: {alpha, kind}` (`train.copy_mask`, `train.copy_weighted`, computed from the batch on the fly; tested). The logged loss and the per-book losses stay unweighted. It is part of the fitout, so these are new ships.
- **Runs.** First Light's round-1 baseline (vocabulary 4,096, learning rate 2e-3, English-original fiction, about 130M tokens) with alpha 1 and 3, kind induction, two seeds each (`fl-copy{1,3}-s{1,2}`, `make_first_light.py --copy`), queued after round 1 and before round 2. Alpha 0 is the round-1 baseline. About 1.5 to 2 hours.
- **Rule, written before any of them sails.** The copy-weighted tack wins only if, across its two seeds: (1) at least one star (previous-word or duplicate-word, by one head or shared, and the Nevermore) lights in fewer steps than at alpha 0; and (2) the final Forgotten Tomes score is no worse than at alpha 0, beyond the two baseline seeds' spread; and (3) copy gain (`nevermore/natural_copy_gain`) rises with the lit head: a head that lights without copy gain has not really arrived. Otherwise it does not win, whatever the probes say.
- **Not done, by design:** no loss term rewards a head's star score directly. That would light the star by engineering it rather than find the path, and a head can light without being used for prediction.
- Cheaper alternatives noted for later: a short warm-up of repeated sequences before the shelf (a curriculum `first` of the Nevermore test's kind), verse and refrains (already a lever), and a higher learning rate for the attention weights early on, checked against the sieves (`grad_norm/layer_i/attn`).

## The heading sieve, and the class below 1m (7 November, 08:00, Justin)

- **Heading** (`heading/<group>`, `fleet.SIEVES["heading"]`): every 50 steps, per parameter group (each layer, its attention and feed-forward halves, the two embeddings), the cosine between the group's move over the last 50 steps and its move over the 50 before. Near 1 the tacks keep one angle (the layer has found its heading and is refining it); near 0 they wander; below 0 the layer is coming about. Push and move are sizes; heading is the angle, the sieve that can test Justin's "fix the angle of the tack as low down the stack as possible": do headings settle bottom-up, does a layer's heading settle when its star lights, and does a layer whose heading has settled earn freezing? Recorded in `train.py` beside the move (the previous window's move per weight is kept, about one model's worth of memory); the first heading appears at step 100. Every run starting from 08:00 records it; the running pathfinder does not. Each sieve's plain-English write-up lives in `fleet.SIEVES[...].about`, for the dashboard's Sieves page.
- **The seedling class, `300k`** (`registry.PRESETS`, `LADDER`, kind "nursery"): 2 layers × 64, two heads of 32 (the head size of 1m and 9m, so a head can be carried up whole), vocabulary 2,048: 0.29M parameters (98k non-embedding). Too small to judge books on. Its job: light the first stars in minutes, then become the foundation a 1m is built on (its layers transplanted into the 1m's bottom and frozen or slowed). ## Seeding, and the Seedling voyage (7 November, 08:20, Justin)

- **Growth** (`thorp/growth.py`, tested): a finished smaller run grown into a bigger model that starts out predicting what it did, up to kernel rounding. Width: the residual stream duplicated r times ([x, x], so every LayerNorm sees the same mean and variance), weights that read it tiled and divided by r, weights that write it tiled; the final LayerNorm divided by r so the tied output gives the same logits. Heads (same head size): the old heads first in each layer, the new heads with zero output columns. Feed-forward units likewise. Layers: the old layers at the bottom, the new ones on top as pass-throughs. It needs whole-number width ratios and the same head size, vocabulary and context (300k into 1m: ratio 2; 1m into 9m is 1.5, which Great Expectations will need a zero-padding variant for).
- **Seeding in training** (`seeded_from: {run, mode, lr_scale}` in a spec; `train.seeded_master`): the named finished run, which must share the tokeniser, is grown into the new model at step 0, with an inherit mask. `mode` freeze restores the inherited weights after every tack; slow scales their gradient by `lr_scale` (their weight decay still applies); free trains everything. The log records the inherited share. `seeded_from` is part of the fitout, so a seeded model is a different ship, and its subtitle says what it grew from.
- **The Seedling voyage** (`fleet.VOYAGES["seedling"]`, `scripts/make_seedling.py`, `specs/seedling/`), queued after First Light: the seedling pathfinder (300k, vocabulary 2,048 on the loop pool, English-original fiction read twice, learning rate 3e-3), then the 1m grown from its last checkpoint with the foundation frozen, slowed to a tenth, or free, two seeds each. Outcomes: steps to the previous-word star (one head or shared) and to the Nevermore, and the Forgotten Tomes score. ## Tricks and stars, and the successor trick (7 November, 08:10, Justin)

- **Tricks and stars are different things.** A **trick** is something a model can do, measured from outside by what it bets: copying what followed a word last time, knowing that Wednesday follows Tuesday. A **star** is the mechanism inside that does a trick, measured by looking at the heads: a previous-word head, a Nevermore. `fleet.TRICKS` (key, name, metric, threshold, evaluator, `performed_by`: the stars expected to do it, about) sits beside `fleet.STARS`. A trick done with no star found means it is done some other way; a star lit with no trick performed is a performer with no act (the copy-gain test of the Magician's Apprentice and the copy-weighted tack is this rule).
- **Tricks so far:** **Copying** (`nevermore/natural_copy_gain`, lit at half a nat; performed by the Nevermore resting on the previous-word head) and **The Successor** (`tricks/successor/score`, lit at 0.5; `thorp/evaluators/successor.py`, evaluator `successor`): for five series (days, months, ordinals, numbers, chapter numerals), every run of two consecutive items as a prompt in its natural form ("Monday, Tuesday,", "CHAPTER I.\n\nCHAPTER II.\n\nCHAPTER") and every item of the series as a candidate " <item>"; each candidate's log-probability after the prompt less its log-probability after the lead-in alone (its prior) ranks them; right when the true next item ranks first; chance one in 7 to one in 20. Also `tricks/successor/lift` (over chance) and the share per series. The first version scored every model at or below chance because the prompts ended on a bare space (Thorp's tokeniser joins a space to the next word) and summed log-probabilities favoured short items; both fixed before any run recorded it.

## The bettor's three discovery tests, pre-registered (7 November, 08:40, Justin)

- **The aim.** The bettor (100m) proves three discovery tests, one per strand of the route (reasoning, physics, mathematics), each the Origin test's pattern: an idea found independently by more than one person within a few years, so it was in the books waiting; a cutoff year; a ship trained only on English written before it; named rivals; and a bet: does it prefer the idea? Each has a precursor ablation (the key precursors removed, bytes kept). Quantum physics moves from destination to far horizon. Every class learns as many tricks as it can and carries them up (the dashboard's `thorp/dash/tricks.py`, goal classes as a minimum, never a cap).
- **The shelves on Gutenberg** (checked 08:35 on the local catalogue; a book counts as before the cutoff when every person in its Authors field died by then, the strict rule that loses books by authors who died later): **Origin** (1859): 146 English books on natural history, geology, population and kindred subjects; present: Malthus (six works including the *Essay on the Principle of Population*), Erasmus Darwin's *Zoonomia*, Cuvier's *Essay on the Theory of the Earth*, Paley (*Evidences of Christianity* only, not *Natural Theology*), Gilbert White; missing: Lyell (Gutenberg has only his post-1859 works), Chambers' *Vestiges*, Lamarck in English, and Darwin's *Beagle* (1839, but its author died in 1882; publication-date metadata from Wikidata would admit it). **Energy** (1840): 76 books on physics, heat, mechanics and chemistry; present: Rumford's *Essays*, three by Davy, three by Thomas Young (not his 1807 *Lectures*), Joseph Black; Carnot reached English only in 1890; Joule, Mayer and Helmholtz all after. **Geometry** (1829): 9 books in all; no Saccheri, Lambert or Legendre, and no English Euclid that passes the rule. **Not viable**: dropped, with Mendeleev's gaps in its place. **Mendeleev** (1869): 36 books on chemistry, elements and metals; present: Davy (five), Dalton, Faraday; Liebig's *Familiar Letters* (1843) fails only the death rule. Every subject shelf is thin, so each bettor trains on all the English written before its cutoff (about 0.4B tokens before 1859 by the strict rule, less before 1840), and the subject books are the precursors inside it.
- **Common design.** For each test, 12 matched pairs of short passages in 19th-century prose: the same neutral opening, then the idea or a named rival, matched in length and rare words, never quoting the discoverers. Score per pair: the rival's bits per byte less the idea's on the differing continuation (bits per byte, because each shelf trains its own tokeniser); positive bets on the idea. Floors: the same pairs scored by the untrained model and by a unigram model of the same shelf. Two seeds. The pairs are written and checked against a history of the subject before any bettor trains, and go in `lists/discovery-<test>.csv`.
- **The Origin test** (`origin_test`): natural selection against fixed species, Lamarckian inheritance and special creation. Ablation: without Malthus and Erasmus Darwin (Lyell is not available), bytes kept.
- **The energy test** (`energy_test`): heat as motion, and energy conserved and turning from one form into another, against caloric (heat as a weightless fluid) and against perpetual motion. Ablation: without Rumford and Davy.
- **Mendeleev's gaps** (`mendeleev_gaps`, the summit's stretch): from the pattern of the known elements, bet on the existence and approximate atomic weights of the elements below aluminium, after calcium and below silicon (gallium, scandium and germanium, found 1875 to 1886), against neighbouring wrong values; scored as each candidate value's log-probability against its prior, as the successor trick is. Ablation: without Dalton and Davy.
- **Pass rule, for each test:** across both seeds the bettor prefers the idea over every named rival by more than twice the seed range and beyond both floors; and in the ablation the preference falls by more than the seed range. Short of that, the graded readings of the order-of-magnitude gate apply (a partial pass when it prefers the idea over some rivals; a partial loss when it prefers it only at a bigger class).
- **Trick entries** in `fleet.TRICKS` (keys `origin_test`, `energy_test`, `mendeleev_gaps`; `geometry_test` kept as a known, not viable on Gutenberg in English): metric `tricks/<key>/preference` (mean bits per byte in the idea's favour), lit at 0.1, evaluator not built yet.

## The share rule for matched-pairs tests (7 November, 10:05, Justin)

- **A matched-pairs test is performed when its lift reaches the threshold (0.1) and at least two-thirds of its pairs go the idea's way** (`Trick.min_score = fleet.MIN_SHARE`, read from `tricks/<key>/score`; `fleet.performed(key, metrics)`). 16 of 24 by chance (one in two) happens about one time in 13; the rule stops a mean carried by a few pairs from counting. It applies to all 19 matched-pairs tests, the bettor's included.
- **What it changes on the ledger runs:** the keel pathfinder (300k) performs Again and again, the smith's test (+0.19, 71% right), the mill test (+0.33, 71%) and Malthus and Lyell (+0.13, 67%); the First Light pathfinder (1m) performs Again and again, the refrain test, the seasons test and Malthus and Lyell (+0.28, 71%); spell-vocab4k-v1 (9m) performs Again and again, the refrain test and the seasons test. The breeders' and smith's passes of the 1m, and the 9m's mill and Malthus passes, no longer count.
- **The eternal return chain is graded as designed under the rule** (the keel performs rung 1 only, the pilot and the speller rungs 1 to 3). **The other three chains are not:** a 300k that passes three 21m and 50m tests that a 9m fails says those pair sets have shortcuts a tiny model can take (collocations such as "hot to the touch", "geometrical ratio"), or, at 14 tests a run, chance (about one false pass expected per run). Their pairs are to be audited against the keel before they are trusted: a rung test should stay dark below its class.

## Smoking Qwen, pre-registered (7 November, 11:10, Justin)

- **The claim:** Thorp chains two facts at an order of magnitude below Qwen3 4B: a Thorp of about 400M parameters (a tenth of Qwen3 4B's 4.0B) reaches Qwen3 4B's chaining lift (+0.538, the mean lift on the four 50m rungs). The Mac cannot train 400M, so the proof is a forecast from Thorp's own classes, keel to 50m (`thorp/smoking_qwen.py`, `payload()` for the dashboard).
- **Method:** x = log10 of parameters (counted from the built model), y = chaining lift of each class's best ship (its seeds together); two curves, `linear` and `bending` (quadratic in x); a bootstrap of 1,000 draws resampling the 96 chaining pairs and the seeds; the forecast at 400M with its 5th to 95th percentile band, and P(smoke), the share of draws at or above Qwen3 4B's mark.
- **Backtest, run first, where the answer is known:** Pythia fitted on 14m to 160m predicts 410m at +0.004 (linear, band −0.049 to +0.053; actual +0.077: missed, too low) and +0.143 (bending, band +0.017 to +0.264: inside). Qwen3 fitted on 0.6B and 1.7B predicts 4B at +0.202 (linear, band +0.044 to +0.381; actual +0.538: missed, too low). Chaining lift bends upward with size: the straight line underestimates, so it is the conservative curve; the bending curve has held where it could be tested.
- **Forecastable only when three Thorp classes have a chaining lift above the noise (0.03).** Today none does (keel −0.013, pilot −0.056, speller −0.021): a curve through noise extrapolates nothing, so no probability is claimed (the dashboard shows the curve and "not yet forecastable"). The points that will make it forecastable are the stylist (the two-fact baseline), the 50m (one to two days on this Mac) and, if needed, a 100m (five to eight days).
- **The rule for the claim:** **Smoking Qwen** when forecastable, the backtest still holds, and P(smoke) is at least 0.9 on the linear curve; **probable** when that holds on the bending curve only. Confirmation, when a GPU backend exists: train the 400M itself (compute-optimal, about 8B tokens, roughly 2e19 operations, on the order of 15 H100-hours).

## The knockout, pre-registered (7 November, 13:30, Justin)

- **The question:** is the hypothesis that a model needs the four necessary cards before it can chain bulletproof? No: the evidence is co-occurrence (five chainers, all holding all four), no model has yet been seen chaining without a card, the cards are definitions with thresholds we chose, and Qwen3 1.7B already chains cause and effect (+0.34) with its mover just under the mark (0.20). The Nevermore's case is the strongest (induction heads were shown necessary for in-context learning by ablation); the mover is a hypothesis carried from another circuit; the comparator should matter only for order and quantity.
- **The voyage** (`fleet.VOYAGES["knockout"]`, `thorp/knockout.py`; outside models only, off the training queue): in a model that chains, each card's 8 strongest heads are silenced (their outputs zeroed on every forward pass, `Inside.silenced`) and the logic deck and the four chaining tests are read again; three draws of 8 random heads from no card are the control. The baseline runs through the same explicit attention with nothing silenced (the explicit path in float32 differs from MLX-LM's fused kernel by up to 0.17 nats, the same for every condition).
- **The rule:** a card is **necessary** in a model when silencing it lowers the cause gain (the comparator: the order gain) by at least 0.1 and by more than twice the largest drop any random draw causes; otherwise **not shown**. First on Qwen3 4B (cause +0.94), then the other four chainers.
- **Qwen3 4B, the first knockout (13:44):** no card shown necessary. Silencing each card's 8 strongest heads left the cause gain where it was (baseline +0.92; previous-word +0.89, the Nevermore +0.93, the mover +0.94; the comparator's order gain +0.07 → +0.09), while one draw of 8 random heads cut it to +0.66 (−0.26; the others −0.06 and −0.07). Read: in a 4B with 1,152 heads, 8 is under 1% and each card's job may be spread and redundant; the random draw that hurt (its heads in the result file) is the best lead on where Qwen's chaining lives. Next: the other four chainers, a dose-response (16, 32, 64 heads per card against random sets of the same size), and the damaging draw's heads silenced one at a time. Until then the necessary-cards hypothesis stands as co-occurrence only.

## Cleaning: the text as Thorp reads it (7 November, 18:45, Justin: "do it")

- **Why:** Gutenberg prints books hard-wrapped at about 70 characters and `gutenberg.strip` kept every line: a line break every eight words, 56% of them inside a sentence, about 8% of the pieces a 2,048-vocabulary model predicts. The best 300k's commonest guess after almost anything was the line break.
- **Cleaning versions** (`thorp/cleaning.py`): `raw` (the source's text; every voyage before this, and any spec that names none) and **`unwrap-v1`**: per book a wrap width (the 90th percentile of its line lengths); a paragraph is prose when its lines mostly reach that width and at least 30% carry on with a lowercase word; in prose a line reaching 60% of the width joins the next (a word hyphen at the margin joins whole), a shorter line keeps its break; verse, lists, tables and headings are kept line for line; blank-line runs become one paragraph break. Measured: prose stores 9 → 24 words per break (breaks inside paragraphs 62% → 3%), reasoning 55% → 1%, cause 56% → 9%, verse kept (75% → 73%), nursery rhymes and primers kept. Known miss: a few prose reports half unwrap.
- **Where it is applied:** at read time, in the one reader of book text (`sources.load_text(book, clean)`); the source's raw text stays the record. The spec names it (`data.clean`, hashed: a voyage on clean text is a different voyage); it is a tokeniser setting, so a cleaned tokeniser and its shards live apart from the raw ones (raw moves no id); the held-out decks are encoded with the voyage's tokeniser, so they are cleaned the same way; bits per byte divides by the bytes of the text as read (`Tokeniser.text_bytes`). The tokeniser trainer's corpus cuts lines over 8,000 characters at spaces (SentencePiece silently skips a sentence over 16,384; an unwrapped paragraph is one line). The cards' natural book and the laws stay raw: they are instruments.
- **The VSM:** S5 policy `clean` (enforced, opt-out in words): new voyages read the current version; S3's gate refuses one that does not; S2 lints a voyage seeded from one that read different text (a model carries its tokeniser); S3\* `clean_audit()` checks on the two stores that cleaning still does its job and is deterministic; S4 owns whether a better cleaning is worth a new version. The 158 voyages queued before the rule are excepted by name, as the stores rule was at 16:11 ("let the queue finish"), with the two follow-up patterns; the two four-cards fitouts stay `raw` (`Fitout.clean`), and every new fitout reads `unwrap-v1`.
- **Comparisons:** a voyage on clean text is not compared with a raw one on bits per byte; the first clean voyages should be a fitout's own two seeds, a new baseline.

## Ogden v0.1: one fixed corpus for every class (7 November, 19:20, Justin: "the fitout is a new one called Ogden ... fixed as the pile was for Pythia"; "run as a baseline against 300k, 1m and 9 million")

## The logic tutor, pre-registered (7 November, 19:58, Justin: "Pre-register it")

- **The question.** Can a trick of the reasoning waypoint be *taught* to an Ogden ship rather than read into it, and does a bigger model's writing teach it better than a program's? The trick is chaining two facts (the logic deck, `tricks/logic_test`); its class on the ladder is the 50m, and the base here is the speller on Ogden v0.1 (3.05M parameters on the shared tokeniser), so a pass would bring it down two classes. Reading alone does not buy it: Pythia 410m reaches a chaining lift of +0.077 after 300B tokens.
- **Why teach the trick and not hand over the star.** The Magician's Apprentice moved two heads between keels of one size and failed all four tests (a trick without its deck); the knockout on Qwen3 4B found its chaining in no card (8 random heads hurt more than any card's 8); and the Pythias hold all four necessary cards and chain nothing. So the trick is taught as text, and the stars and cards are read to see whether a mechanism formed, never transferred. Each arm continues from the base's own weights: one trunk, the trick as a change on top of it.
- **The base:** each seed of `fu-ogden-v0-1@9m-pre` at its last checkpoint (`seeded_from`, mode free, the same 2,048-piece tokeniser and `unwrap-v2`). Its own last readings say whether it already holds the Nevermore and the mover, the two cards chaining rests on that Thorp lacks today.
- **The skeletons** (a seeded generator, to be written): two facts about invented things and the conclusion that follows from them, in four of the logic deck's relations: order, cause, membership and proportion. Each conclusion is checked by its relation's rule (transitivity, the chain of events, inclusion, multiplication) before use. **Held out of all teaching:** the counterfactual relation and every three-fact chain, so both are transfer readings. The invented words are drawn fresh, disjoint from the logic deck's and absent from the Ogden corpus's lexicon.
- **The same skeletons written two ways, at equal tokens:**
  - **tutor:** a bigger model writes each skeleton as a short passage of strict Basic English: Ogden's 850 words in their regular forms, names, numbers and the skeleton's invented words, nothing else; varied wording, the facts in either order, the conclusion drawn with a marker ("so", "because of this"). The teacher is Qwen 3.8 27B (4-bit, on this Mac, the weights already downloaded for the Forgotten Tomes), its licence checked before generation. It returns each passage with its facts and conclusion restated as triples, which must match the skeleton; a passage with any word outside the allowed set gets one rewrite, then is dropped. A 100-passage sample is read by hand before any voyage sails: if fewer than 95% keep the skeleton's logic, the prompt is rewritten.
  - **template:** the same generator's skeletons in fixed sentence frames, written fresh (none of the logic deck's frames). Frames are shorter than prose, so this arm draws more skeletons to fill the same tokens. No model's text is in it.
- **Kept apart from the tests:** no run of six words shared with any row of the logic deck or of the chains' pair files (`lists/tricks/`). **The four inventions kept out:** no skeleton has the form of a discovery the bettor is tested on (variation, inheritance and selection; a quantity kept through a change; a row repeating with a period; a return of the same). The content words (numbers excepted) of the four chains' 50m rungs (`nature.csv`, `mill.csv`, `between.csv`, `pigeonhole.csv`) are listed before generation, and a passage that uses one is dropped. The list is recorded with the fitout. Those four tests are also a reading below, so they must not be taught.
- **The stage, the same for every arm:** 16M tokens (about 490 steps at 32,768 a batch; the base read about 200M), half new text and half the base's own corpus. Ogden draws are fixed by seed and taken in whole books.
  - **tutor:** 2M tokens of tutor text and a 2M-token draw of Ogden v0.1, read four times, shuffled.
  - **template:** 2M tokens of template text and the same draw, four times.
  - **replay** (the control): the same draw and a second 2M-token Ogden draw, four times. The base reads on, untaught.
  - The base's optimiser (AdamW, batch 32,768, clip 1.0, bf16), warm-up 50 steps to 3e-4 (between the base's final 1e-4 and its peak 1e-3), cosine to a tenth. The light set (stars, Nevermore, cards, logic) every 32 steps; the full set (adds the Forgotten Tomes and the chains) at the end. The base's last full reading is step 0.
  - Three arms, two seeds, six voyages, each seed's arms from that seed's base: `fu-ogden-v0-1@9m-<arm>-s<seed>`.
- **The verdicts, pre-registered, at the last reading across both seeds:**
  1. **The trick is taught** (per taught arm, against replay). PASS if both seeds perform chaining on the logic deck by the deck's own rule (gain 0.1 or more, two-thirds of items right), and both seeds' gain is above both replay seeds'.
  2. **The teacher is worth having** (tutor against template). PASS if both tutor seeds' gain is above both template seeds'.
  3. **Nothing lost** (a guard on each taught arm). The mean Forgotten Tomes score of its two seeds is no worse than replay's by more than 0.02 bits per byte. An arm that passes 1 and fails 3 is a partial pass: it taught the trick at the cost of the reading. The speller's goal reading (the keyed 4-word guess on Ogden words) is reported beside it.
- **Readings reported, never verdicts:** transfer (`gain_counterfactual` and `lift_three_hop`, both never taught; `lift_padded`, does the chain survive a distractor); the cards over the stage (the Nevermore, the mover and the comparator, and which lights first, the mover or the gain; a trick performed with no card lit is done some other way); the four chains' 50m rungs (Nature's breeder, the mill, the between and the pigeonhole tests); kinks at the stage boundary (the named-stages question).
- **What each outcome means:**
  - **Tutor passes 1 and 2:** a bigger model's writing teaches reasoning that reading does not; the taught line is worth building. Next: the same at the 1m (how far down it goes) and at the grown 21m with all five relations.
  - **Template passes 1, and the tutor does not beat it:** the forms teach, not the teacher. Thorp's logic comes from programs, which carry no modern knowledge, and no bigger model is needed for it.
  - **Neither passes 1:** at 3M parameters chaining is not taught in 16M tokens. The test moves to the 21m once grown, or the stage lengthens.
- **Before it sails (not queued):**
  - The skeleton generator, the two writers and the six specs.
  - The teacher's generation rate, measured on 1,000 passages before the full 2M tokens are drawn.
  - The two Ogden 9m voyages home.
  - **An S5 policy for taught text (Justin's decision, open):** which fitouts may read text that is not a period book; how such voyages are marked; that they stay off the period leaderboard and are never compared with their teacher on the Forgotten Tomes. Today the `ogden` policy matches fitout names by prefix, so an `ogden-…` taught fitout would pass it unmarked, and the stores rule would need a `data.opt_in` for each taught arm. The replay arm is period-pure and needs neither.

## Maincoder-1B on the Forgotten Tomes (7 November, 19:30, Justin: "how can i smoke maincodes maincoder 1 b" … "Yes, score it")

- **Why this model:** Maincode's `Maincoder-1B` (Melbourne; 1.03B parameters, Apache 2.0, a code model, 76% on HumanEval) is the smallest model an Australian company has released that I could find. Sovereign Australia AI's Ginan is described as an 8B Llama 3.1 fine-tune; Maincode's Matilda has no published size or weights. "Smoking" it, in Thorp's terms, is a Thorp at a tenth of its size (about 100M) reaching its mark, on Thorp's own measures: not on code, which nothing printed before 1930 contains.
- **The port** (`backend/scripts/mlx_ports.py`): mlx-lm cannot load its architecture (`MaincoderForCausalLM`). It is Qwen3-like (GQA 16/4, head 96, SwiGLU, RMSNorm, tied head), with two differences: the rotation pairs adjacent dimensions (the "traditional" form), and the query and key norms come *after* the rotation, so mlx-lm's Qwen3 would score it wrongly. The port downloads only the weights (`model.safetensors`, 2.05 GB), the config and the tokenizer (Qwen2's; start token `<|endoftext|>`), and never runs Maincode's Python.
- **The port checked before it was trusted:** on 6 KB of this repository's Python and 6 KB of *Pride and Prejudice*, 1.041 and 1.232 bits per byte with adjacent pairs, against 2.406 and 2.005 with rotate-half. Norms before the rotation give 1.046 and 1.230, so that difference barely shows. A greedy Python completion is coherent.
- **The score** (`data/compare/Maincode--Maincoder-1B__hole-cards-unseen.json`; raw text, 1,024-token windows from an empty context, as every outside model; 297 seconds): **1.123 bits per byte**. Beside it: Qwen3.5 0.8B 1.138, Qwen3 0.6B 1.234, and Thorp's best 9m (`pool-400-v1`) 1.632, behind on all 16 books, by 0.34 (*A Happy Woman*) to 0.73 (Wilson's *History of the American People*, vol. 5). Fiction is closest; history and reference books are furthest. No book is flagged as probably seen elsewhere: its best is 0.19 below its own mean, against the deck's 0.5.
- **What smoking it takes:** a Thorp of about 100M parameters at or below 1.123 on the Forgotten Tomes, 0.51 below the 9m today, and a harder mark than Qwen3 0.6B's. On the 0.22B legal tokens fetched so far it is not expected; the corpus ceiling (`ships/plans/corpus-ceiling.md`) puts 3.9 to 5.3B legal tokens in Gutenberg alone.
- **S2:** outside-model scoring now takes the helm (`vsm.at_sea`, kind "score", in `score_external.py`), so it waits in port while a voyage is at sea, and the next voyage waits for it.

## The deck and the Navigator's Wager (7 November, 21:00 to 21:30, Justin: "collecting cards to get to next levels"; "keep the deck a certain size to keep within a human's context window"; "predicting where the cards fall based on pulling a specific lever"; "I should be able to choose the lever, bet and then queue an experiment")

- **The deck** (`backend/thorp/viable/s5_policy/deck.py`, S5): 16 cards in four constellations of four (about four chunks fit in working memory): ♠ Copying (previous-word, duplicate-word, induction, the Nevermore), ♥ Position (the sink, the delimiter, words back, the counter), ♦ Comparing (number-spotter, order-word, the comparator, the scales), ♣ Carrying (the rare word, premise-marker, the bridge, the mover). Stages as Pokemon evolve: a Basic is one head in one layer; a Stage 1 is played only above a played Basic of its constellation in an earlier layer; a Face is traded in when its cards are held in order and its ability (what it does: "a machine is what it does") passes: the Nevermore's is a copy gain of 1.0 nats, the mover's a one-hop lift of +0.1, the scales' an order gain of +0.1. Cards without a reading are uncharted (the counter, number-spotter, order-word, premise-marker). ## Pretraining in phases: the metre scaffold on the keel (7 November, 23:15, Justin: "pretraining is broken up into phases, the insertion of the metre topics and then normal training on content"; "schedule it after the 21m run")

- **The scaffold** (`optim.scaffold`, `backend/thorp/train.py`): a second loss pulls chosen heads' attention toward a metre card's pattern, a rule over the token ids, so no teacher is needed. **previous-word** attends to the piece before. **induction** attends to the pieces that followed earlier copies of this piece, shared evenly among them. The pull is a cross-entropy from the pattern to the head's attention, averaged over the scaffolded heads, added at this step's weight. The model reads Ogden text throughout; only the pull changes. **Three phases of one voyage:** **metre** (full weight, to `hold`), **fade** (eased linearly to zero by `fade`), **content** (the language-model loss alone). `fade: null` never releases it. Recorded every step: `scaffold/weight`, `scaffold/loss`, `scaffold/phase`. The Watch panel draws the phases under the stage bar, with the pull and its weight on the loss chart. The picked heads' weights come from `GPT.forward_attending` (the ordinary forward pass, with those heads' attention computed out beside it). Only rule-made metre cards can be pinned so far (previous-word, induction); the other eight metre cards follow if this works.
- **Why the fade, not a hard switch:** a head pinned while nothing above it learns to read it is held from the page, and the language-model loss lets it drift once released. Reading text all along lets the layers above come to depend on it, and the fade is the test of "by heart".
- **Placement:** the layout the 21m found for itself (previous-word moved to its layer 1 at steps 1,280 to 1,600; induction rising in layer 3 above it), squeezed into the keel's 2 x 2 heads: previous-word on layer 0 head 0, induction on layer 1 head 0. The other head in each layer is free.
- **The arms (Ogden v0.1, the 300k keel, 8,216 steps, two seeds each), queued right after the 21m:** `fu-ogden-v0-1~metre@300k-pre-s1/s2` (full to 5% = step 411, faded by 25% = step 2,054) and `fu-ogden-v0-1~metre-held@300k-pre-s1/s2` (never released: the ceiling). Both read `pips` as well. **The control is home:** `fu-ogden-v0-1@300k-pre-s1/s2` (Nevermore look 0.004 / 0.003, copy gain 0.085 / 0.062, previous-word 0.36 / 0.33 in layer 1, the last; judge-book bpb 1.853 / 1.860).
- **Predictions, fixed now:**
  1. **During metre**, both arms hold previous-word in layer 0 (at least 0.5) and the induction look in layer 1 (at least 0.3): expected; if not, the pull is too weak, and the arm says nothing about the idea.
  2. **By heart:** at the end, the fade arm still has previous-word in layer 0 at 0.5 or more, and the induction look at 0.3 or more in layer 1, on both seeds: **the claim**. Expected for previous-word, a coin toss for induction.
  3. **The Nevermore traded in** (natural copy gain at least 1.0) on the fade arm, on both seeds, where the control reads 0.06 to 0.09: hoped for, not expected. Above 0.5 on both seeds already counts as the ♠ chain doing work.

- **The design.** A fitout's stage declares its books as a *selection* (`thorp/selection.py`, stored in `s3.stages.compose`) instead of pointing at a hand-made list. `thorp select compose <fitout>` reads the selection and the library's *facts* (`thorp/library_facts.py`, one row a book, `s3.library_facts`) and writes a fixed list, `lists/composed/<fitout>-<stage>.csv`, as a recipe reads it; the fitout's own shelf is never touched. Every composing is a row in `s3.compositions`: the selection and its hash, the facts' fingerprint, the list and its sha1, the counts, the funnel of rules (books left after each), and the gate's library prechecks (period, decks, stores) read on the list. Deterministic: the same facts and selection write the same bytes.
- **What a selection can say.** (1) **Language weights**, shares of the words (`{en: 1.0}` today); a language named with no book to fill it is an error, never a silent zero. (2) **Ogden-ness**, a bar (the score `lists/ogden-*-scores.csv` already holds; a book on the bar is scored again from its text, because the files round to four places) and the rank a trim keeps. It is not yet a sampling weight. (3) **A period**, `start` and `end` years, inclusive. (4) **Filters** by kind, voice, source and bookshelf, include and exclude; and **weights** by kind, voice or source, as shares of the words, trimmed lowest-ranked first to the largest total that fills them all. Also: `as_of` (the library as it stood that day), `dedupe` (one copy a title), `carry` (a list kept whole), `strike` (named books, with the reason), `append` (a list added after, as the tutor's passages are), a word budget.
- **Always on, whatever the selection says** (the gate's rules, not choices): `recipe` books only, none read by the decks, no shuffled control, no credited name dead after 1955 (S5 `period`).
- **Which date: the writer's year, estimated, with its basis kept.** No catalogue we hold carries a publication or first-edition year (Gutenberg's "Issued" is the day the file was released), so a *publication* or *first-edition* period cannot be applied honestly yet. What it carries is the credited names' birth and death years, which is what the gate already reads. A book's year is, in order: **published** (the year recorded when archive.org books were fetched: 16 books); **floruit**, the writer's birth year + 40, no later than their death (the classical age of a writer's prime: 3,298 books); **late**, death - 25 where only the death is known (16); else **undated** (322, mostly Britannica articles, *Punch* and *Notes and Queries* volumes, volumes by "Various", and ancient dramatists with no dates). "The writer" is the translator if one is credited (it is their English), else the first credited author, else the first credited name with dates. **A book with no date** has no year: a period with bounds leaves it out unless it says `undated: include`; with no bounds it is read as usual. The gate's death-year rule is separate and always on.
