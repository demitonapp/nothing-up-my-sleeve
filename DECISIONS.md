## Repository and tooling

- Repository root is `~/Source/Thorp` (the brief's `thorp/`); the package is `thorp/` inside it, built with hatchling so `uv run thorp` works.
- Python pinned to 3.12 with `.python-version`; `pytest` and `ruff` are in a `dev` dependency group, not runtime dependencies.
- Ruff selects E, F, I, B, UP and ignores E501, since `ruff format` owns line length (100) and a few docstring lines run over.
- `thorp/paths.py` (not in the layout) is the one place paths are decided; `THORP_DATA` and `THORP_LEDGER` override them so tests run in a temporary directory.
- `thorp/chinchilla.py` (not in the layout) holds the section 11 formula so the dashboard and README share it.
- `thorp id SPEC` was added to print a spec's run id without running it.
- `thorp ledger SQL [PARAMS...]` binds every `?` to the most recent finished run when no parameters are given (or to `--run ID`), so the section 10 query runs as written.

## Acquisition

- The User-Agent names the project and reads its contact from `THORP_CONTACT`; no personal email is hard-coded into the repository.
- Resolver language match is "the row's language is one of the catalogue row's `;`-separated languages", since a few catalogue rows list two.
- Title normalisation is NFKD, drop combining marks, lowercase, punctuation to spaces, collapse whitespace; CJK passes through unchanged.
- The author "surname" is the last word of the normalised author field; a row with no author is matched on title alone.
- Book ids are `pg<gutenberg id>` (for example `pg1342`), so the source is visible in every shard name and ledger row.
- Raw downloads are cached as `data/texts/gutenberg/{id}.txt`; stripping happens on read, so a better stripper never needs a re-fetch.
- The manifest `set` column is inferred from the list's filename (`hole` in the name means `hole-card`).
- Licence removal when there is no END marker cuts at the first line beginning "End of (the) Project Gutenberg" or "*** END OF" or "START: FULL LICENSE".
- `data/resolution.csv` holds every list fetched so far; refetching a list replaces only that list's rows.
- Overrides (`lists/overrides.csv`) pick the right volume or translation where the resolver chose wrongly: Thousand Nights vol. 1 (3435, not vol. 10), Herodotus vol. 1 (2707, not vol. 2), Divine Comedy Longfellow complete (1004, not Norton), Dhammapada Max Müller (2017), Nibelungenlied Needler (7321), Kalevala Kirby vol. 1 (25953), Consolation of Philosophy H. ## Tokeniser, shards and data

- Tokeniser id is SHA-1 of the sorted book ids; settings that differ from the defaults (vocab 16384, byte fallback, coverage 0.9995) are appended to the key, so another vocabulary on the same books is a different directory.
- SentencePiece is trained lossless: identity normalisation, no dummy prefix, extra whitespace kept, newline as a user-defined piece, digits split. `decode(encode(text)) == text`, so bits per byte charges for every byte, whitespace and line breaks included.
- SentencePiece samples at most 4 million lines (`input_sentence_size`) with `max_sentence_length=16384`; ids are unk 0, bos 1, eos 2, no pad.
- Byte-fallback rate per book (fraction of tokens that are byte pieces) is in `stats.json` beside bytes per token.
- Shards are written to a temporary name and renamed, so an interrupted write never leaves a half shard that would be "written once".
- Hole-card books are also sharded (under the run's tokeniser) so evaluation tokenises once; they are never in a recipe or in tokeniser training.
- `order: shuffled` means: books concatenated in a seeded shuffle per pass, cut into non-overlapping `context + 1` windows, and the windows themselves dealt in a seeded shuffle into batches. Without the window shuffle every batch would be 32 consecutive windows of one book.
- A window's family (for the per-batch family mix) is the family of the book its first token comes from; the mix is logged as `data/family/<family>` every 50 steps.
- The remainder of a pass that does not fill a batch is dropped.

## Model and training

- The "9m" preset as specified (6 layers, width 192) has 2.66M non-embedding and 3.34M embedding parameters (6.0M total, 16,384 × 192 token plus 1,024 × 192 position embeddings), not the brief's "about 6M non-embedding + 3M embedding". The layer and width table wins; N in the Chinchilla formula is the measured non-embedding count.
- A `tiny` preset (2 layers, width 64) exists for tests only.
- LayerNorm without bias, GELU (tanh approximation), initialisation N(0, 0.02) with output projections scaled by 1/√(2·layers).
- Attention uses `mx.fast.scaled_dot_product_attention` with a causal mask.
- "bf16 parameters with fp32 optimiser state": the model computes in bf16; the optimiser keeps an fp32 master copy of the weights plus fp32 Adam moments, and the bf16 weights are refreshed from the master after every step. Checkpoint `model.safetensors` holds the fp32 master.
- Weight decay (0.1) applies to every parameter, norms and embeddings included (MLX AdamW's default); no bias correction (MLX's default).
- Learning rate: linear warmup over 200 steps to 1e-3, then cosine to 1e-4 at the last step.
- The loss and its gradient are compiled with `mx.compile` (model state as inputs and outputs); clipping and the optimiser step run eagerly in fp32.
- Steps are numbered from 1 (step N is after N updates); evaluation runs at every multiple of `eval.every_steps` and at the final step; checkpoints at every multiple of `checkpoint.every_steps` and at the final step.
- `param_norm` is the L2 norm of the fp32 master weights; `grad_norm` is the pre-clip global norm.
- On resume, ledger rows recorded after the checkpoint step are deleted, so the metric series has no duplicates; wall time accumulates across resumes via `state.json`.
- A run that raises is marked `failed: <ExceptionType>` in `runs.status`.
- The git commit recorded is `HEAD`, with `-dirty` when tracked files have uncommitted changes.

## Evaluation

- Each held-out book is scored as `[EOS] + tokens + [EOS]`, so every token is predicted once with no free first token; `tokens` in the evals row is the number of predictions (book tokens + 1).
- Windows do not overlap; each starts with an empty context, which slightly overstates loss relative to a sliding window.
- Set means are unweighted means over books; `eval/<set>/ce_mean_en` and `bpb_mean_en` are the same over English books only, and the Chinchilla gap uses `ce_mean_en`.
- Missing hole cards are listed in the run's `eval_sets` artifact (`missing`) and in the run log, since the `runs` table has no column for them.
- Samples are stored as one `samples` artifact (JSON list of prompt, temperature, text) and one `top10` artifact per eval step; temperature sampling is seeded by the step.
- Determinism: on the GPU, MLX's embedding-gradient scatter-adds are not bitwise reproducible (about 1e-9 in fp32, 6e-5 in bf16), and Adam amplifies this, so two identical GPU runs drift apart. The resume test therefore runs on the CPU, where MLX is bitwise reproducible; the seed-2 run measures the run-to-run spread that matters.

## The observation layer and the next runs (6 November, evening)

- The loss function returns the per-window losses beside the batch mean (MLX passes auxiliary outputs through `value_and_grad` and `compile`); the mean of the window means is the batch mean, so the `loss` row is unchanged. Window losses are summed per recipe book and written every 50 steps as `loss/book/<id>` (the mean over that window), never per step: a hundred books at every step would be most of the ledger.
- The sieves are per parameter group from `model.param_groups()`: `tok`, `pos`, `layer_i`, `layer_i/attn`, `layer_i/mlp`. Every 50 steps: `grad_norm/<g>` (pre-clip push), `param_norm/<g>` (size of the fp32 master), and once a full 50-step window has passed since the last record, `update_norm/<g>` (the move since then) and `update_ratio/<g>` (move over size). The step-1 record carries no move. `grad_norm/layer_i` keeps its old name and value.
- The kink (where a layer's push changes regime) is computed on the page from the rows, as the least-squares break of a two-line fit to log10 of the norm, and is never stored: it is derived, like everything else the page shows.
- Trait probes (`evaluators/probes.py`): difference-of-means directions fitted on eight evenly spaced windows per recipe book, scored on sixteen per hole card, per layer, as an AUC. Found means held-out AUC ≥ 0.8 at some layer with at least two hole cards on each side; thinner than that is `untestable`, so a direction can never be a book-identity direction in disguise. Labels come from `lists/traits.csv` by list title (fiction, verse, first_person; blank skips the book for that trait) and the family one-vs-rest from the manifest. The `probes` artifact carries every trait's status and reason; `probe/<trait>/layer_i` and `/best` are the metric rows.
- The first sample prompt is a law of physics ("For every action there is an equal and opposite"), not the capital of France: a law does not move with the date, and no book on the shelf states it, so the bar for "reaction" is a tracer for a textbook shelf. The other three are first lines of books on the shelf and are a memory check, labelled as one on the page. The top-10 artifact carries its prompt.
- The page is read in sections (Betting, Books, Languages, Sieves, Attention, Traits, Runs) with a nav bar; the claim panel at the top states the hypothesis, the measure, the prediction and the falsifier, and computes the ledger's reading (best shelf, shelf-to-shelf difference, seed spread, which side of twice the spread). `/api/compare` serves every run's hole-card bpb against tokens seen for it; `/api/run` joins the traits and the latest `probes` artifact.
- `specs/smoke-10-v2.yaml` is smoke-10 with the probes evaluator; `hundred-by-reach-v1-seed2.yaml` keeps its original spec because the run had already started on it (the error bar must not change under the run).
- The pool (`scripts/make_pool.py`): the earliest Gutenberg transcriptions, by id, that pass both legal checks on the catalogue's own author dates (a person without dates is refused), no periodicals or index entries, no edition of a hole card by title, nothing already in the manifest. Family from the subject tags for translations, Germanic for an English original. Fiction and verse labels come from the subject tags; first_person is left blank. 560 drawn (ids 1..816); `scripts/cut_pool.py` keeps the hundred plus the first 300 of at least 100 KB as `lists/pool-400.csv`, and cuts the fiction and non-fiction halves to the same bytes within 2%.
- The next shelf is sized to the model, not the hand: about 400 books read twice, roughly 65M unique and 130M seen tokens, against Chinchilla's twenty tokens per parameter (53M to 120M for this preset). Six specs: the pool, its fiction half, its non-fiction half, each with two seeds, in that order, queued by `scripts/queue_next.sh` after seed-2 and the fetch.
- `scripts/` holds one-off builders and the queue; they are not part of the package and read the repository paths directly.
- Every spec carries a `ship`: a short name for the run (Dinghy, Argo, Endeavour, Hispaniola, Mayflower; II for seed 2). `name` and `ship` are the two keys left out of the run id, so naming a run never changes it; the ledger's `runs` table gained a `ship` column (added in place on an older ledger) and the page shows the ship wherever a run is named. The three runs already on the ledger were named by hand.
- The page's sections are tabs (one shown at a time, chosen by the URL hash, charts resized on show), so a person navigates the deck rather than scrolling it.
- The overview strip carries four things only: the ship (with run name, id and status), the kink findings in one line (firm kinks by layer with which way they went, the tentative count, the earliest), tokens a second, and the ETA (wall time once finished). Preset, tokens seen, the hole-card mean and the Chinchilla yardstick moved to a strip at the top of the Betting tab. The kink fit starts where warmup ends (the learning-rate peak); a kink is firm after ten records when the two-line fit removes a quarter of the one-line residual, and is labelled turned up, turned down, flattened, steepened, eased or bent by the signs of the two slopes.

The run's spec row is untouched; the held-out books are refused against the recipe as at training; an `eval_sets` artifact is written at the scored step; and `clear_step` now deletes only the evals rows of the sets being written, so a re-score never removes a score the run already has. Before this, a re-score cleared every evals row at the step.

- The Betting tab's matched-tokens table interpolates each run's own first eval set linearly at 16M, 32M and 64M tokens and leaves a dash outside the curve (no extrapolation); `/api/compare` now carries every set a run was scored on (`by_set`) and the per-layer push and learning rate, so the page computes each run's earliest firm kink with the same fit as the Sieves tab. The truth gap is `truths` minus `hole-cards-v2` (or `hole-cards` if the run has no v2 rows) at the same step; with only a final-step re-score it is one point per run, and the "change since first scored" column fills only for runs that train with the truths deck in `eval.sets`.
- Endeavour started at 20:09, while these edits were being made; the training loop is unchanged by them (the scoped `clear_step` deletes the same rows when the sets are the run's own), and its commit reads `-dirty`.
- Trait floors (`probes`): each tested trait also gets `floor_bow` (the same difference-of-means probe on each window's token histogram, projected as the mean of the direction over the window's tokens, so no window-by-vocabulary matrix is built) and `floor_init` (the probe on the run's model at initialisation, `train.init_model`, built from its own seed and cached once per run). `emergent` is found and best AUC at least 0.05 above both floors. The page splits YES into "emergent" and "in the tokens". A floor that raises is recorded on the trait as `floor_error` and never fails the run: the queued training runs after Endeavour load this code. `build_model` reseeds MLX's global generator, which is safe mid-run only because training draws nothing from it after the model is built (the data order is numpy with explicit seeds; samples use explicit keys).
- The curiosity ladder (`evaluators/curiosity.py`): six rungs on the held-out books, each against the untrained model and, for the two probe rungs, a bag of tokens. Thresholds are constants at the top of the module and in each `curiosity` artifact: calibration r ≥ 0.3; novelty and question AUC ≥ 0.8 and 0.05 above the floors; late-minus-early loss ≤ −0.1 nats and copy gain ≥ 0.5 nats; expectancy and asking ≥ 0.1; rungs 1, 3, 5, 6 must also beat the untrained value by 0.1. Rung 2's familiar side and rung 4's fitting sentences are 64 evenly spaced recipe books. Rung 4 strips the end punctuation from questions and statements alike but keeps interrogative words, which the token floor accounts for. Rung 6 subtracts the text's own high/low ratio of question marks, so a model that only copies the text's habit scores zero. The ladder is in order when no present rung sits above an absent one, untestable rungs skipped. It runs in the re-score chain and in the phase 3 specs, not in the night's queue.
- The Traits tab reads every step's `probes` artifact (`/api/run` → `probes_all`, later rowid wins at a step), with a step selector and a sort: sieve layer (the layer where the held-out AUC peaks, with that layer's kink from the push), first step found (over every step on the ledger), best AUC, or name; the sort is remembered per viewer in localStorage. The half-life chart's labels are made unique with the book id: two volumes cut to 40 characters had shared one bar slot.
- Phase 3 specs are written and not started (`hundred-traits-v1`, `pool-400-traits-v1`, each with a seed-2 twin; ships Beagle and Resolution): eval every 100 steps on `hole-cards-v2` and `truths`, refusing all three held-out lists, with `ce_bpb`, `samples`, `probes` and `curiosity`. The held-out decks are about 27 MB, so an eval every 100 steps adds materially to each run's wall time; the brief's 2.5 hours for four runs is an underestimate.

## The content experiment, pre-registered before any shelf is cut (6 November, 20:50)

- **Question.** Holding the model, the tokens and the test fixed, does the shelf a model is trained on change how well it guesses books it has never seen, by more than chance alone does?
- **Ships.** Five shelves, three ships each, all at the 9m preset, English only, the same bytes and the same passes: Flotsam (three different random draws of legal English catalogue books, seeds 1 to 3: the null), Paralus (the Greek polis, primary texts), Dhow (the Islamic golden age, primary), Santa Maria (the continental Renaissance in English translation, primary), Cutty Sark (books written about those three ages by later authors). Primary texts arrive in translations printed 1800 to 1929; every person in a book's catalogue Authors field died by 1955.
- **Size rule.** Every shelf is cut to the same bytes B, the largest B at which every shelf can be filled with no single work above a third of it (a work counts once across its translations and volumes: all the Nights are one work, both Korans one, Jowett's Plato one, Vasari's Lives one, Grote's History one). B is set from the fetched sizes and recorded below this entry; the rule is not changed after the sizes are seen.
- **Primary measure.** English bits per byte on the `neutral` deck (held-out 19th and 20th century prose with no Greek, Islamic or Renaissance book in it), read at the same tokens for every ship: the smallest final tokens-seen of the fifteen, by linear interpolation.
- **The verdict rule.** Let F be the three Flotsam scores, its centre their mean and S their range. Content has a detectable bearing if some curated shelf's three-ship mean lies more than 2S from F's centre; otherwise it has none at this size and this shelf size, and that is the finding. Quality: a primary shelf differs from Cutty Sark if their means differ by more than twice the larger of the two shelves' ranges. Type: two ages differ by the same rule. The page computes all three from the ledger.
- **Secondary readings, not part of the verdict:** each age's own held-out deck (the transfer matrix), each ship's best point over training, the truths deck, the trait probes and the curiosity ladder.
- **Known limits, stated now:** translation is confounded with canonical (the primary shelves are translations, Cutty Sark and Flotsam mostly written in English); about 3M unique tokens a shelf is far below the 9m model's appetite, so a null says "not at 9m on shelves this size".
- **Addendum, 20:55, before any shelf is cut: content against traits, kinks and sieves.** The same rule (a curated shelf's three-ship mean more than 2S from the Flotsam centre, S the Flotsam range) is applied to four more outcomes, each a secondary verdict on the page: (1) traits: each testable trait's best held-out AUC at the final step, its emergent status against the floors, and its first step found; (2) kinks: the earliest firm kink step and each layer's firm kink step (push, two-line fit from the learning-rate peak); (3) sieves: each layer's mean log10 push and mean update ratio over the last quarter of training; (4) the curiosity ladder: the highest rung present. The probes test on every held-out book the ships are scored on (the neutral deck and the three age decks), so fiction, verse and first person all have books on both sides.
- **The content ships' optimiser differs from the earlier runs, the same for all fifteen:** `batch_tokens` 8192 (not 32768) and `warmup_steps` 100 (not 200), so a shelf of about 10 MB read four times is about 1,300 steps with about 24 sieve records after the learning-rate peak, enough to fit a kink. Evaluation every 200 steps. These runs are compared with each other, never with Argo or Endeavour.
- **Translations and legal checks for the shelves:** every person in the catalogue Authors field died by 1955 and has a death year (a person with no dates is refused); every translator, editor or adapter was born in 1760 or later, which keeps the translations to those printed in the 19th and early 20th centuries and excludes Early Modern English renderings (Urquhart's Rabelais, Robinson's Utopia, Fairfax, Sale, Scott); children's retellings (of the Nights above all) are excluded. The held-out books for each age (Greek, Islamic, Renaissance) are removed from that age's shelf.
- **Amendment, 21:00, after counting titles and before measuring any bytes: the one-third cap is dropped.** Under the legal rules the Islamic shelf outside the Nights is the Koran (Rodwell), Rumi (Redhouse's Mesnevi, Davis), Jami (Davis) and the Rubaiyat, about 3 MB, so the cap would have set every shelf near 3 MB, under a million tokens, and starved all fifteen ships. Instead B is the smallest shelf's whole size, every shelf is cut to B, and each shelf's largest-work share is recorded and shown beside its result. The Islamic shelf is therefore mostly the Nights (Burton, Payne, Lane, Forster), which is what the Islamic golden age is in English on Gutenberg; its result is read as that. Cherágh Ali's 1885 tract is off the Islamic shelf (a 19th-century argument, not a golden-age text). Burckhardt's Civilisation of the Renaissance is refused (its translator has no dates in the catalogue).
- **The cut (21:05).** B = 12.45 MB, set by the third random draw (38 books; the first two drew more than they needed). Every shelf is within 2% of B: Greek 52 books (Plato 55%), Islamic 14 (the Nights 91%), Renaissance 19 (Erasmus 33%), about the ages 15 (Symonds 40%), random 36, 27 and 38. About 3.4M tokens a shelf, four passes, about 1,640 steps at 8,192 tokens a batch. Books that did not fetch (no plain-text file, or unresolved) are simply not on their shelf. Evaluation every 400 steps (four times and the final step), so that the fifteen ships and the four kinks-against-traits ships fit before 07:00. The shelves' fiction and verse labels were read from the catalogue's subject and bookshelf tags (one step wider than the pool's subjects-only rule); first person is unlabelled on these shelves, so that trait reads untestable for them.
- **Ship names (21:05, Justin):** Banks-style names that say what each run is for, a label only (not hashed). Content: Whatever Washed Ashore (random; Something Else Washed Ashore and A Third Tide's Worth are the second and third draws), What Athens Wrote, Mostly The Thousand Nights, Florence, In Translation, Merely Describing Greatness; a second seed is "…, Rolled Again", a third "…, Third Roll". The night queue's unstarted ships were renamed in place (ids unchanged): Only Things That Happened (Mayflower), Four Hundred Books, Second Opinion (Endeavour II), Made-Up People, Rolled Again (Hispaniola II), Things That Happened, Rolled Again (Mayflower II). Hispaniola was already sailing and keeps its name.
- **Evaluator failures (21:13).** In `run_evaluators`, only `ce_bpb` (the score) may stop a run; any other evaluator that raises is logged, written as an `eval_error` artifact at that step, and skipped. The content ships are the first to run the curiosity ladder and the probe floors on real shelves during training, and all fifteen share that code, so an untested failure there must not cost the night. The page's run picker (header) sets the run every per-run panel shows; panels that compare every run are tagged ALL RUNS.

## The ladder: one job per size (6 November, late, Justin)

- **Five rungs, each with one job; these are the first class of ships.** Presets in `thorp/models/registry.py` (`67m` and `300m`, never run, became `50m` and `350m`; `100m` is new). Total parameters include the 16,384 × width token table and 1,024 × width positions.

  | preset | layers × width | non-embedding | total | where | the job |
  | --- | --- | ---: | ---: | --- | --- |
  | `9m` | 6 × 192 | 2.7M | 6.0M | this Mac mini | spelling, punctuation and the statistical laws of text |
  | `21m` | 8 × 320 | 9.8M | 15.4M | this Mac mini | grammar and style: agreement, sentences, register held through a passage |
  | `50m` | 12 × 512 | 37.7M | 46.7M | rented GPUs | paragraphs, and the third point for fitting this corpus's own size curve |
  | `100m` | 12 × 768 | 84.9M | 98.3M | this Mac mini (about 5 to 8 days) | the Origin test: the Mac's flagship |
  | `350m` | 24 × 1024 | 302.0M | 319.8M | rented GPUs | the top of the Origin curve |

- **The Origin test.** Trained only on English printed before *On the Origin of Species* (cutoff 1858, the Darwin–Wallace papers), does the model find natural selection less surprising than matched rival accounts (fixed species, Lamarckian inheritance, special creation), and does that preference grow with size and shrink when the precursor shelf (Malthus, Lyell, Paley, Chambers' *Vestiges*, the breeders, the *Beagle* voyage) is taken off at the same bytes? A base model does not derive; the claim is about betting, which is what this harness measures. The result is the curve over 9m, 21m, 50m, 100m and 350m, not any one model. Known hurdles: the catalogue carries no first-publication date (author death year is a strict stand-in that loses, for example, Dickens before 1859); revised editions leak (Lyell revised the *Principles* into the 1870s); translators' notes leak; and the pre-1858 English corpus is about 0.4B tokens when counted by the strict rule that every person in a book's Authors field died by 1858 (2,919 catalogue books at the mean fetched size; see `plans/leonardo-pilot.md`), so `350m` (about 6.4B tokens at twenty a parameter) will be short of data at that cutoff.
- **Rented GPUs need a second backend.** The harness is MLX-only (`registry.FAMILIES`), so `50m` and `350m` need a PyTorch model behind `thorp/models/backend.py`'s protocol before they can run off the Mac. Not built yet.
- **Each rung is tuned once, then frozen.** A rung's settings are swept against its own job first; its shelf experiments then run at the frozen settings, so the ledger's comparisons inside a rung stay like for like.

## The 9m rung's scoreboard and tuning sweep (6 November, late)

- **`bpb_split` evaluator** (`thorp/evaluators/bpb_split.py`): bits per byte on each held-out book split by the kind of byte predicted: `word_inside` (a letter after a letter: spelling), `word_start` (a letter after a non-letter: word choice), `punct` (Unicode P*), `space`, `newline`, `digit`, `other`. An apostrophe between letters counts as inside the word. A token's loss is shared evenly over its bytes, the convention under which the classes add back to the book's bits per byte weighted by byte share; the closing EOS has no bytes and is reported as `eos_bits`. Metrics `eval/<set>/split/<class>/bpb_mean[_en]` and `share_mean[_en]`; the per-book bits and bytes are the `bpb_split` artifact. Token bytes come from the pieces (`▁` is a space, `<0xNN>` a byte), checked to rebuild War and Peace byte for byte.
- `ce_bpb.book_ce` now sums per-token float64 losses from `book_losses` (which `bpb_split` shares) instead of float32 sums per batch; the score moves only at rounding, and the seed-2 pool runs that started after this edit run it.
- **`laws` evaluator** (`thorp/evaluators/laws.py`): the model writes 16 streams of 640 tokens from an empty context at temperature 1 (key seeded by the step); the reference is 16 excerpts of the English held-out books at fixed seeded character offsets; both are cut to 150 words a stream, so vocabularies that spend different tokens per word are measured on the same amount of text. Laws, each as `laws/model/<law>` and `laws/ref/<law>`: `nonword_rate` (words never seen in the recipe; the reference's rate is the floor), `zipf` (minus the log-log slope of frequency on rank over words seen twice or more), `heaps` (log-log slope of vocabulary on words read), `word_len`, `word_len_js` and `punct_js` (Jensen–Shannon divergence in bits from the reference's word-length and punctuation mix), `punct_per_100w`, `unbalanced_per_kw` (orphan or unclosed brackets and curly double quotes, plus odd straight double quotes, per thousand words) and `cap_after_stop` (share of sentence ends followed by a capital). Laws drift with sample size, so they compare across runs only at these constants. The written and reference texts are in the `laws` artifact. The recipe lexicon is built once per process.
- `run_evaluators` clears a step's evals rows only when `ce_bpb` is among the evaluators (the only one that writes them), so `thorp eval RUN --evaluators bpb_split laws` adds the split and the laws without touching the score.
- **The sweep** (`scripts/make_9m_specs.py`, order in `specs/9m-order.txt`): Endeavour's shelf, passes and optimiser with one setting changed, two seeds each, evaluators `ce_bpb bpb_split laws samples probes`: vocabulary 4,096 (*Smaller Pieces*) and 8,192 (*Half The Pieces*) against Endeavour's 16,384, and context 256 (*Short Memory*) against 1,024; seed 2 is "…, Rolled Again". The 16,384 / 1,024 cell is Endeavour and its seed 2, re-scored with the split and the laws. Same bytes, not same tokens: a smaller vocabulary spends more tokens and steps on the same shelf, and its embedding table is smaller (4,096 × 192 = 0.8M against 3.1M), which is the point. Bits per byte is fair across tokenisers.
- **The night's order changes (supersedes "content question first" in *Earn each size*):** `scripts/queue_9m.sh` replaces `scripts/queue_content.sh` (stopped while still waiting, before it ran anything). After `queue_next.sh` and `queue_rescore.sh` exit, it re-scores every finished 9m run with `bpb_split` and `laws`, runs the sweep, then the fifteen content ships and the four traits ships as before. The content and traits specs now also carry `bpb_split` and `laws` (none had started, so only their run ids move); their other settings are unchanged, so the content experiment's pre-registered rule stands. The content ships run at 16,384 whatever the sweep finds; if the sweep moves the 9m settings, later 9m shelf experiments use the new ones.

## The speller curriculum (6 November, 22:10, Justin)

- **Question.** Does teaching spelling first help the 9m model spell? Three arms, two seeds each, queued after the vocabulary and context sweep (appended to `specs/9m-order.txt`, written by `scripts/make_curriculum_specs.py`), all on `lists/pool-400-spellers.csv` (Endeavour's 400 books plus the 13-book speller shelf `lists/spellers.csv`: McGuffey's Primer, First to Sixth Readers and Spelling Book; Oliver Optic's Spelling-Book for Advanced Classes; F. W. Hamilton's printer's primers on Punctuation, Capitals, Word Study and English Grammar, and Division of Words; 2.6 MB, every person died by 1955), so all three share one tokeniser:
  - *Mixed Lessons*: the speller shelf shuffled in. Against Endeavour, the content without the order.
  - *Primer First*: the speller shelf before everything else in the first pass. Against Mixed Lessons, the same tokens in another order.
  - *Lines Written a Hundred Times* (Justin's mantra): the six rule books (`lists/spelling-rules.csv`, 0.57 MB) read a hundred times before everything else in the first pass, about 57 MB on top of the pool. Compared with the others at matched tokens.
- **Prediction, stated before any run:** a speller-first advantage on inside-word and punctuation bits per byte early in training that narrows by the end; a large effect from the mantra on the rules' own wording and little on the held-out books. Curriculum results in small language models (the BabyLM challenge, 2023–24) have mostly been small.
- **`data.first` and `data.first_repeats`** (`thorp/data.py`): in the first pass only, the `first` books (each read `first_repeats` times, every repeat in its own seeded shuffle) are cut into windows and dealt before the rest, which follow as usual; later passes are ordinary. `order: curriculum` in a spec is a label; the behaviour comes from `first`. Without `first` the stream is unchanged batch for batch (tested).
- No word list ("all known words") is fed: a dictionary has every word once, which teaches the wrong frequencies (against Zipf) and, at 16,384 pieces, little spelling of common words, which are single tokens. The spelling books are word lists already, in the order a child met them.
- **Popovers.** Every metric on the 9m page has an ⓘ that says what it measures, which direction is better and why; "What we measure" has a "better is" column.

## The data levers: distinct text against total reading (6 November, 22:30)

- **Why.** Endeavour spells best of the 9m runs (inside-word 1.602 bits per byte against Argo's 1.735, forty times the Argo seed gap of 0.003), but it read both more distinct text (54.5M unique tokens against 16.8M) and more text in all (109M against 67M), so the finding cannot say which lever bought it.
- **Design.** Endeavour is the centre; five runs move one lever each, all with Endeavour's tokeniser (`tokeniser.train_on: lists/pool-400.csv`, new: a spec may train its tokeniser on another list, so shelves that differ only in what they read share one), optimiser and evaluation (`scripts/make_lever_specs.py`). Same total reading, about 109M tokens: 800 books once (*Never the Same Page Twice*), 400 twice (Endeavour), 200 four times (*Read It Again*), 100 eight times (*Worn Spines*). Same distinct text, Endeavour's 400 books: once (*One Pass Only*), twice (Endeavour), four times (*Four Times Round*). Seed 1 only: the inside-word seed gap is 0.003, far below the effects being looked for; the laws' noisier readings are read with that in mind.
- **Shelves** (`scripts/cut_levers.py`, run once the second draft is fetched): `pool-800` is pool-400 then the unused books of the first draft and then `lists/pool-draft-2.csv` (500 more books drawn by `make_pool.py` under the same legal rules; the draft's overrides and trait labels appended as `make_pool.py` does), at least 100 KB each, lowest ids first, to twice pool-400's bytes; `pool-200` and `pool-100` are the first half and quarter of pool-400's bytes in one seeded shuffle, so pool-100 sits inside pool-200. Every v1 or v2 hole card and every truths book is left out by Gutenberg id.
- Prediction (Muennighoff et al., 2023): up to about four passes count almost as fully as new text, so 200 × 4 should be close to Endeavour and 100 × 8 clearly worse; 800 × 1 a little better.

## Thorp against Qwen: the Forgotten Tomes (6 November, 23:40, Justin)

- **Goal.** Thorp's first version to compare with Qwen 3.8 27B is a 2.7B model: a tenth of the parameters. The comparison is Thorp's own measure, bits per byte on held-out books, which does not depend on the tokeniser, so both models are scored on exactly the same bytes.
- **The Forgotten Tomes** (`lists/hole-cards-unseen.csv`, drawn by `scripts/make_unseen_deck.py`; Justin's name): 16 English books, 7.7 MB, released on Gutenberg on or after 2026-08-05, the day Qwen/Qwen3.8-27B appeared on Hugging Face (its model card gives no data cutoff), so not in its training data by way of Gutenberg; every person in Authors born 1500 to 1880 and dead by 1955; 100 KB to 1 MB each. The metric is the **Forgotten Tomes score**: mean bits per byte on this deck, lower is better. Known limit: new to Gutenberg is not the same as never on the web (Goldsmith's essays and Wilson's History of the American People exist in other editions), so a book Qwen scores far better on than the rest is read as probably seen. No current recipe holds any of them (their Gutenberg ids are above 79,000, and every pool draw skips books already in the manifest); new specs should list it under `refuse`, and the re-score's refusal check would catch an overlap.
- **Scoring outside models** (`scripts/score_external.py`, `uv run --group compare`; `mlx-lm` is in an optional `compare` group so training never depends on it): the same stripped text, the model's own tokeniser, a start token in front, non-overlapping windows of 1,024 predictions each from an empty context, as `ce_bpb`. Qwen's tokens hold more bytes than Thorp's, so a 1,024-token window gives Qwen somewhat more context: a small edge to Qwen, stated rather than corrected. Qwen 3.8 27B is scored in the 4-bit MLX conversion (`mlx-community/Qwen3.8-27B-4bit`, 16 GB; the bf16 model needs 54 GB), which moves its score a little; Qwen 3.5 0.8B (bf16) is scored too as a small reference. Results in `data/compare/<model>__<list>.json`.
- **Thorp's side** (`scripts/score_thorp_unseen.sh`): every finished run's latest checkpoint re-scored on the deck with `ce_bpb`.
- **Precedence (Justin):** the scoring runs ahead of the 9m queue. `scripts/queue.sh` now also runs `cmd: <shell command>` lines; the three scoring steps head `specs/queue.txt`, after the run that was training when they were added.
- **Expectation, stated now:** Qwen wins by a wide margin at every Thorp size so far, because the data gap (trillions of tokens against at most a few billion legal pre-1930 tokens) is the binding constraint, and a 2.7B model wants about 54B tokens. The contest Thorp can make its own is per token of training text; every rung goes on that chart.

## The 1m proxy (6 November, 23:55, Justin: ahead of the 9m sweep)

- **Why.** A 9m speller run is about half an hour of training and an hour of evaluation; the outer loop (runs as steps, the Forgotten Tomes score as the error signal) needs far more, faster steps.
- **The preset** `1m`: 4 layers × 128, 4 heads, vocabulary 4,096 (at 16,384 a model this small would be mostly word table): 1.44M parameters (0.79M non-embedding). Peak learning rate 2e-3 (small models take a higher one), warmup 100. Lean evaluation: `ce_bpb` and `bpb_split` on the Forgotten Tomes only, once at the end. Measured 146k tokens a second (2.3 times 9m: overhead-bound at this size), so a Chinchilla-sized run (28M tokens) is about 3–4 minutes with its evaluation.
- **Calibration before trust** (`scripts/make_proxy_specs.py`): Argo's, Endeavour's, Hispaniola's and Mayflower's shelves and passes, plus a second Argo seed for the noise, at 1m. The proxy is trusted for a kind of question only if it ranks these as the 9m runs rank on the Forgotten Tomes (scored by `scripts/score_thorp_unseen.sh`). Deep traits are out of its reach by design.

## The order-of-magnitude gate, pre-registered (7 November, 00:05, Justin)

- **The test.** Thorp at about 60M parameters (the 50m rung or a little above: a tenth of the challenger) against Qwen3 0.6B (`mlx-community/Qwen3-0.6B-bf16`, released 2025-04, the smallest Qwen 3), both scored in bits per byte by the same window rule on two decks of unseen-since-Qwen period books: the Forgotten Tomes (redrawn balanced by kind, poetry included) and a sealed second deck drawn the same way and opened only for this verdict. Thorp's number is the mean of two seeds. If it passes, the same gate is run one rung up, until the 2.7B against Qwen 3.8 27B.
- **The binary verdict, PASS or FAIL.** PASS only if all of these hold, otherwise FAIL: (1) Thorp's mean bits per byte is at or below Qwen's on the Forgotten Tomes; (2) the same on the sealed deck; (3) the difference survives the noise: Thorp's two seeds both at or below Qwen.
- **Under a FAIL, one graded reading, with its caveats stated beside it:**
  - *Partial pass*: within 0.10 bits per byte of Qwen on both decks, or below Qwen on at least one kind of book (poetry, fiction, history, ...) on both decks.
  - *Partial loss*: behind by more than 0.10 on both decks, but below Qwen on at least one kind on one deck, or the gap to Qwen closing by more than a third from 9m to 50m (so the next rung could close it).
  - *Clear loss*: behind by more than 0.10 on both decks, no kind won on either, the gap not closing. The road is wrong as built; the recipe is rethought before any larger run.
- **Caveats always reported with the verdict:** Qwen's 1,024-token windows hold more bytes than Thorp's (an edge to Qwen); tomes on which Qwen beats its own deck mean by more than 0.5 bits per byte are flagged as probably seen elsewhere, and the verdict is also given without them; the training-data gap (Qwen 3 about 36T tokens, Thorp at most a few billion).
