# The UI audit (9 November) — where the debt is, and what to do about it

Justin: *"the UI is being pretty buggy. we implemented ShadCN but can you do a full audit of the UI and where there's debt,
bad code reuse and overcomplicating things."*

The honest summary: the dashboard is a **5,671-line script** with 222 functions, 66 API calls, 303 `innerHTML` writes and a
hand-rolled router, rendered into 26 Astro components. ShadCN was adopted as **class-name helpers**, not as components.
The bugs of the last two hours are not accidents — they are the predictable output of that shape.

## What is actually there

| piece | size | what it does |
|---|---|---|
| `scripts/dashboard.js` | **5,671 lines** | routing, 26 views, 66 fetches, every tab's renderer |
| `components/*.astro` | 26 files | static markup per page, with ids the script fills |
| `lib/*.js`, `lib/*.ts` | 803 lines | `ui.ts` (ShadCN class builders), charts, tables, format, deck, journey, stages, reader |
| daemon (`dash/server.py`) | — | one endpoint per panel, ~120 of them |

## The five structural debts

### 1. No component model — markup and behaviour are separate files joined by ids

A panel is an Astro `<section id="…">` plus a `drawX()` function that finds the id and writes a template string. Nothing
checks the two agree. This morning: `#deckclass` was removed from the page but `classDeck()` still ran; `#goalroute` was
moved to another tab and the renderer had to be gated by hand; `#goaltable`'s renderer needed a null guard. **Every tab
move is a joint edit in two files with no compiler help.**

### 2. No error boundary — one throw blanks the page

The render is a long list of `if (modelTab === …) drawX(r)` calls. A throw in any one of them stops everything after it,
and the page shows *nothing*, which reads as "no data". That is exactly the training tab's symptom right now, and it has
happened three times today (train journey, shipbuilder TDZ, deck panel). I added `safe()` wrappers as a band-aid this
morning; the real fix is one boundary **per panel** with its error rendered in place of the panel.

### 3. Duplicated fetch-cache-guard, 62 times

`if (!xData) { try { xData = await get('/api/x') } catch (e) { return; } }` appears 62 times, each with its own
`xKey`/`xAt` cache, its own staleness rule, and its own silent `return` on failure. There is no request layer, no
invalidation, no "stale" indicator — so a panel that fails to fetch looks identical to a panel with no rows.

### 4. Duplicated charts

Four Plotly call sites, and today I wrote **the same star-chart spec three times** (`starJourney`, `sizeJourney`,
`sopchart`) with slightly different margins. Every new panel grows the divergence.

### 5. ShadCN is a veneer

`lib/ui.ts` exports class-string builders (`cardCls`, `pillCls`, `tabsCls`…) — useful, but there are **no actual
components**: no Dialog, no Popover, no Tabs behaviour, no Select behaviour. Every interactive control is still hand-wired
(`b.onclick = …`, `sel.onchange = …`), which is why the maths selector reset itself and the shipbuilder's tabs needed
hand-rolled state. The design system is being *named* in class strings while the behaviour is bespoke.

## The bugs those debts produced today

| bug | cause | fix |
|---|---|---|
| Training tab blank (now) | one drawer throws before the others render | per-panel boundary (in progress: a red bar names the drawer) |
| Shipbuilder blank | `paintChoices` const used before declaration (TDZ) | hoisted to a declaration — fixed |
| Maths selector jumping to an old voyage | options rebuilt on every read, fallback list overwrote the choice | build once per size+version — fixed |
| Overview deck panel gone but renderer alive | markup removed, script not | guarded — fixed |
| Goals route moved but page blank | drawer ordering, unfixed | boundary + the red bar will name it |

## What I would do, in order

1. **Fix the blank training tab now** — reload once; the red bar names the drawer. That is a five-minute fix once named.
2. **A `panel()` helper** — one function that takes an id, a fetcher, a renderer and a cache key, and does the
   try/fetch/guard/error-in-place dance once. Removes ~62 copies of the pattern and makes "no data" and "broken"
   visually distinct.
3. **One chart module for the star chart** — the three copies collapse to one function with options.
4. **Give ShadCN real components** — at minimum `Tabs`, `Select`, `Dialog` with behaviour, not just classes; the
   shipbuilder and the queue page are the two places it would pay for itself immediately.
5. **Split `dashboard.js` by view** — `views/training.js`, `views/scoring.js`, etc., with the router importing them.
   That is mechanical but it is what stops the "one throw blanks everything" class of bug.

Steps 2 and 3 are a day's work and remove most of the class of bug we hit today; step 4 is the one that makes the UI feel
engineered rather than assembled; step 5 is the structural fix.

## What I would *not* do

Not rewrite in React. The 26 Astro components and the daemon's endpoints are fine; the problem is the single script and
the missing boundaries, not the framework. A rewrite would cost a week and reproduce the same shape at higher altitude.
